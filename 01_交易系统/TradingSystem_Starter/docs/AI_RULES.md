# AI_RULES.md — MQ5 + Crypto 自动化交易系统工业标准

Version: 2.0
Owner: 项目负责人
Primary AI Workflow: ChatGPT Pro + Codex + Trae + MT5
Secondary Tools: Gemini / Grok 仅作为备用，不进入默认开发流程

---

## 0. 项目定位

本项目用于开发可长期维护、可回测、可扩展、可由 AI 协同迭代的自动化交易系统。

核心方向：

- MQ5 EA
- 数字货币自动化交易
- AI 信号过滤
- 多策略框架
- 多品种扩展
- 风控优先的交易系统

最高原则：

> 先保证系统稳定、可回测、可维护，再追求收益。

## 1. 工具分工

### 1.1 默认主流程

只使用以下四个核心工具：

1. ChatGPT Pro：总架构师、策略设计、风控设计、代码审查、回测分析、迭代决策。
2. Codex：本地工程执行、写代码、改文件、重构、修复编译错误。
3. Trae：IDE、文件管理、查看代码、配合 Codex 执行项目开发。
4. MT5：编译、回测、参数测试、实盘或模拟盘验证。

### 1.2 Gemini 使用规则

Gemini 不参与默认开发。

允许使用场景：

- 单次日志或报告过长，ChatGPT 当前窗口不方便处理。
- 只做总结，不做最终技术决策。
- 只做辅助归纳，不直接生成最终代码。

禁止使用场景：

- 禁止让 Gemini 直接重写核心 MQ5 文件。
- 禁止让 Gemini 改风控逻辑。
- 禁止让 Gemini 与 Codex 同时修改同一个模块。

### 1.3 Grok 使用规则

Grok 不参与默认开发。

允许使用场景：

- 查询币圈热点。
- 查询市场新闻。
- 查询社交情绪。
- 辅助判断某个币种是否存在突发事件风险。

禁止使用场景：

- 禁止让 Grok 写 EA 代码。
- 禁止让 Grok 设计最终风控。
- 禁止根据 Grok 的市场观点直接改交易策略。

### 1.4 多 AI 协作禁令

禁止多个 AI 同时对同一文件、同一模块、同一风控逻辑提出修改。

每个开发任务只能有一个主执行 AI：

- 架构与逻辑：ChatGPT
- 代码落地：Codex
- 编译与运行：MT5 / Trae

## 3. 总体开发原则

必须遵守：

1. 禁止重绘。
2. 禁止时间穿越。
3. 禁止未来函数。
4. 禁止 Tick 作弊。
5. 禁止无止损交易。
6. 禁止无限马丁。
7. 禁止无限网格。
8. 禁止重复开仓。
9. 禁止信号模块直接下单。
10. 禁止风控绕过执行模块。
11. 禁止硬编码关键参数。
12. 禁止无日志交易。
13. 禁止未经回测直接实盘。
14. 禁止让 AI 在不知道项目规则的情况下改代码。
15. 禁止多个 AI 同时改同一个核心逻辑。

必须做到：

1. 所有 EA 必须可回测。
2. 所有交易行为必须有日志。
3. 所有风控参数必须集中管理。
4. 所有入场条件必须清晰可解释。
5. 所有出场条件必须清晰可解释。
6. 所有模块必须低耦合。
7. 所有模块必须单一职责。
8. 所有修改必须记录原因。
9. 所有版本必须能回滚。
10. 每次迭代只改一个主要变量。

## 4. MQ5 代码规范

### 4.1 编程风格

采用面向对象 + 模块化。

命名规则：

- 类名：PascalCase，例如 `RiskManager`。
- 函数名：PascalCase，例如 `CanOpenTrade()`。
- 变量名：camelCase，例如 `dailyLossLimit`。
- 常量名：UPPER_CASE，例如 `MAX_RETRY_COUNT`。
- 枚举名：PascalCase，例如 `TradeDirection`。
- 文件名：PascalCase，例如 `RiskManager.mqh`。

### 4.2 函数限制

- 单个函数尽量不超过 80 行。
- 一个函数只做一件事。
- 不允许在函数中混合信号、风控、下单、日志四种职责。
- 复杂逻辑必须拆分为小函数。

### 4.3 参数规则

所有可调参数必须使用 `input` 或集中配置。

禁止：

```mq5
if(spread > 300) return;
```

推荐：

```mq5
input int InpMaxSpreadPoints = 300;
if(spread > InpMaxSpreadPoints) return;
```

### 4.4 MagicNumber 规则

MagicNumber 必须集中管理。

格式建议：

```text
策略ID + 品种ID + 周期ID + 版本ID
```

例如：

```text
10010501
```

含义：

- 1001：策略 ID
- 05：M5 周期
- 01：版本

### 4.5 注释规则

注释必须解释“为什么”，而不是重复“做什么”。

错误示例：

```mq5
// 判断是否大于0
if(value > 0)
```

正确示例：

```mq5
// 避免在无有效ATR数据时计算动态止损
if(atrValue <= 0)
```

## 5. EA 生命周期标准

### 5.1 OnInit

必须按顺序执行：

1. 加载输入参数。
2. 初始化日志模块。
3. 初始化配置模块。
4. 初始化指标句柄。
5. 初始化信号模块。
6. 初始化风控模块。
7. 初始化执行模块。
8. 初始化 AI 接口。
9. 检查交易环境。
10. 输出启动日志。

### 5.2 OnTick

必须按顺序执行：

1. 更新当前 Tick。
2. 检查是否新 K 线。
3. 更新市场数据。
4. 更新账户状态。
5. 更新仓位状态。
6. 更新风控状态。
7. 检查交易时间。
8. 检查点差。
9. 更新指标信号。
10. 更新 AI 信号。
11. 合成最终信号。
12. 检查是否允许开仓。
13. 检查是否允许加仓。
14. 检查是否需要平仓。
15. 执行交易动作。
16. 管理止损止盈。
17. 写入日志。

### 5.3 OnDeinit

必须执行：

1. 输出停止原因。
2. 保存运行状态。
3. 释放指标句柄。
4. 关闭外部连接。
5. 输出本轮统计。
6. 清理资源。

## 6. 模块职责边界

### 6.1 SignalEngine

职责：

- 计算指标。
- 判断趋势。
- 判断入场信号。
- 输出方向、强度、置信度。

禁止：

- 禁止下单。
- 禁止修改仓位。
- 禁止修改止损。
- 禁止直接访问交易执行函数。

输出格式建议：

```text
Direction: BUY / SELL / NONE
Strength: 0-100
Reason: EMA trend aligned, ATR valid, breakout confirmed
```

### 6.2 RiskManager

职责：

- 判断是否允许交易。
- 控制最大亏损。
- 控制最大连续亏损。
- 控制最大仓位。
- 控制单笔风险。
- 控制日内熔断。

禁止：

- 禁止产生交易信号。
- 禁止直接下单。

### 6.3 ExecutionManager

职责：

- 唯一下单入口。
- 唯一平仓入口。
- 唯一修改止损止盈入口。
- 处理滑点、重试、订单错误。

禁止：

- 禁止自行决定策略方向。
- 禁止绕过 RiskManager。

### 6.4 PositionManager

职责：

- 读取当前持仓。
- 判断是否已有仓位。
- 判断是否重复开仓。
- 管理持仓状态。

### 6.5 Logger

职责：

- 统一输出日志。
- 记录交易动作。
- 记录错误。
- 记录风控拒绝原因。
- 记录信号来源。

## 7. 交易信号标准

每一个交易信号必须包含：

1. 方向：BUY / SELL / NONE。
2. 信号强度：0-100。
3. 入场原因。
4. 失效条件。
5. 止损来源。
6. 止盈来源。
7. 是否经过趋势过滤。
8. 是否经过风控确认。

禁止只返回：

```text
BUY
```

必须返回类似：

```text
BUY | Strength=78 | Reason=EMA fast above EMA slow + price above trend filter + ATR valid
```

## 8. 风控标准

### 8.1 必须支持的风控

第一阶段必须实现：

1. 最大点差过滤。
2. 单笔固定风险。
3. ATR 动态止损。
4. 最大持仓数量。
5. 同方向重复开仓限制。
6. 每日最大亏损限制。
7. 最大连续亏损暂停。
8. 最小保证金检查。
9. 交易时间过滤。
10. 回测模式兼容。

第二阶段再实现：

1. 最大回撤熔断。
2. 分批止盈。
3. 保本移动。
4. 追踪止盈。
5. 波动率过高暂停。
6. 新闻/事件过滤。
7. AI 置信度过滤。

### 8.2 日亏损熔断

规则：

- 当日亏损达到设定比例，停止新开仓。
- 已有仓位是否平仓，由策略参数决定。
- 熔断触发后必须写日志。

### 8.3 连亏暂停

规则：

- 连续亏损达到设定次数后，暂停新开仓。
- 暂停时间必须可配置。
- 新交易日可选择是否重置。

### 8.4 仓位计算

禁止固定手数长期写死。

仓位必须支持：

```text
Lot = AccountRisk / StopLossDistance
```

并检查：

- 最小手数。
- 最大手数。
- 手数步进。
- 保证金要求。
- 合约规格。

## 9. 订单执行标准

下单前必须检查：

1. 是否允许自动交易。
2. 是否连接正常。
3. 是否交易时段。
4. 点差是否合格。
5. 是否已有重复仓位。
6. 风控是否允许。
7. 止损是否有效。
8. 手数是否有效。
9. MagicNumber 是否正确。
10. 注释是否包含策略版本。

订单失败必须记录：

- 错误码。
- 品种。
- 方向。
- 手数。
- 价格。
- 止损。
- 止盈。
- 重试次数。

## 10. 日志标准

日志格式：

```text
[Time][Module][Level][Symbol][Magic][Event][Detail]
```

示例：

```text
2026-05-09 14:21:01 [RISK][WARNING][BTCUSDT][10010501] DailyLossLimitReached dailyLoss=-5.2%
```

日志级别：

- INFO：普通信息。
- WARNING：风险提示。
- ERROR：错误。
- TRADE：交易动作。
- SIGNAL：信号。
- RISK：风控。
- DEBUG：调试。

必须记录：

1. EA 启动。
2. EA 停止。
3. 每次信号产生。
4. 每次风控拒绝。
5. 每次下单。
6. 每次平仓。
7. 每次修改止损止盈。
8. 每次订单失败。
9. 每次熔断。
10. 每次参数版本变更。

## 11. 回测标准

每次回测必须记录：

1. 策略版本。
2. 品种。
3. 周期。
4. 起止时间。
5. 参数设置。
6. 初始资金。
7. 交易次数。
8. 胜率。
9. 盈亏比。
10. 最大回撤。
11. 连续亏损次数。
12. 净利润。
13. 期望值。
14. 主要问题。
15. 下一步修改。

禁止只看净利润。

优先级：

```text
稳定性 > 回撤控制 > 风险收益比 > 净利润 > 交易次数
```

## 12. 测试周期规则

建议第一轮测试周期：30 天。

第一阶段目标不是赚钱最大化，而是验证：

1. AI 协作流程是否稳定。
2. Codex 是否能按规则改代码。
3. ChatGPT 是否能稳定做架构和复盘。
4. EA 是否能保持模块化。
5. 每次修改是否可追踪。
6. 回测结果是否越来越可解释。

### 每日记录

每天记录：

- 今天改了什么。
- 为什么改。
- 谁负责改。
- 是否编译通过。
- 是否回测。
- 结果如何。
- 是否引入新问题。

### 每周复盘

每周复盘：

- 哪些规则有效。
- 哪些规则太复杂。
- 哪些模块最容易出问题。
- Codex 是否遵守规则。
- 是否需要调整项目结构。
- 是否需要引入 Gemini/Grok。

## 16. 第一阶段项目范围

第一阶段只做一个最小可用系统。

范围：

- 单品种：BTCUSDT 或你当前常用品种。
- 单周期：M5。
- 策略：EMA 趋势 + ATR 止损。
- 风控：点差、固定风险、日亏损、连亏暂停、最大持仓。
- 执行：开仓、平仓、止损、止盈。
- 日志：必须完整。
- AI：只预留接口，不接入真实模型。

暂不做：

- 多币种。
- 多账户。
- 高频。
- 复杂 AI 模型。
- 网格。
- 马丁。
- 链上数据。
- 新闻自动交易。

## 17. 第一阶段验收标准

一个版本只有满足以下条件，才算通过：

1. 编译无错误。
2. 回测能完整跑完。
3. 无重复开仓异常。
4. 无无止损订单。
5. 日志能解释每一次交易。
6. 风控触发能被记录。
7. 参数能集中调整。
8. 信号模块没有下单代码。
9. 执行模块是唯一交易入口。
10. 修改过程可追踪。

## 18. 长期目标

长期目标是建立：

- 多策略。
- 多品种。
- 多周期。
- 多交易所。
- AI 信号过滤。
- 模块化风控。
- 自动化回测。
- 自动化复盘。
- 可由 ChatGPT + Codex 持续维护的量化开发体系。

最终标准：

> 策略可以换，但框架不能乱。信号可以错，但风控不能失控。AI 可以辅助，但交易纪律必须由规则控制。
