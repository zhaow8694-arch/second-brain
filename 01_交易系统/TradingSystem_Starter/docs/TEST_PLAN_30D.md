# TEST_PLAN_30D.md — 30天测试计划

目标：测试 ChatGPT + Codex + Trae + MT5 的量化开发流程是否稳定。

测试重点不是收益最大化，而是验证：

1. 规则是否能约束 AI。
2. Codex 是否能稳定按规则改代码。
3. ChatGPT 是否能稳定输出架构和复盘意见。
4. EA 框架是否越来越清晰。
5. 每次修改是否可追踪、可回滚。
6. 回测结果是否能解释。

---

## 第1周：建立框架

目标：

- 完成目录结构。
- 完成 EA 基础生命周期。
- 完成 Logger。
- 完成 Config。
- 完成基础 SignalEngine。

验收：

- 编译通过。
- OnInit / OnTick / OnDeinit 日志正常。
- 不要求盈利。

---

## 第2周：加入风控

目标：

- 点差过滤。
- 最大持仓。
- 固定风险。
- ATR 止损。
- 日亏损熔断。
- 连亏暂停。

验收：

- 风控拒绝必须有日志。
- 任何订单必须有止损。
- 不允许重复开仓。

---

## 第3周：加入执行管理

目标：

- 统一下单入口。
- 统一平仓入口。
- 订单失败处理。
- 止损止盈修改。
- MagicNumber 统一。

验收：

- SignalEngine 不能下单。
- ExecutionManager 是唯一交易入口。
- 订单错误必须记录。

---

## 第4周：回测与迭代

目标：

- 跑至少 3 个市场阶段。
- 分析趋势期、震荡期、急跌期表现。
- 每次只改一个主要变量。
- 确认框架是否适合继续扩展。

验收：

- 输出一份完整复盘。
- 确定是否进入 v0.2.0。
- 决定是否加入 AI 信号接口。

---

## 30天结束后的判断标准

通过条件：

1. 项目没有变乱。
2. 模块职责清楚。
3. Codex 修改可控。
4. 回测能稳定复盘。
5. 风控没有被破坏。
6. 日志能解释交易。

不通过条件：

1. 多个 AI 输出互相冲突。
2. 代码结构越来越乱。
3. 每次修改引入新 bug。
4. 风控经常被绕过。
5. 回测结果无法解释。

结论：

- 如果通过，进入多策略/AI接口阶段。
- 如果不通过，先重构规则，不进入复杂策略。
