# MQL5 EA 项目完整开发大纲 - 自适应市场状态交易系统 v1.1

## 一、项目概述
**项目名称**：JessieOBS 自适应市场状态交易系统
**开发平台**：MetaTrader 5 (MQL5)
**核心理念**：先判断市场环境（趋势/震荡），再执行对应策略，实现智能切换。
**目标**：构建一个具备**市场状态识别 + 智能切换 + 全局风控 + 性能极致优化**的完整工程级 EA 系统。

---

## 二、系统整体架构（事件驱动隔离版）

【Bar 级低频触发】 -> 行情判断模块（核心大脑：状态机 + 滞后过滤机制）
                         ↓
                   ┌─────┴─────┐
                   ↓           ↓
【Tick 级高频触发】趋势执行模块   震荡执行模块
                   ↓           ↓
【Tick 级高频触发】入场出场逻辑模块（统一执行与旧仓位接管）
                         ↓
【OnTransaction触发】全局风控模块（硬核熔断 + 净敞口监控 + 风险监控）
                         ↓
                    最终交易执行

## 三、五个核心模块详细职责（MQL5 实现要点）

### 1. 行情判断模块（核心大脑，Bar 级触发）
- **功能**：实时判断当前市场属于 `Trending`（趋势）还是 `Ranging`（震荡）。
- **推荐指标组合**：ADX(14) + iMA(200) + ATR(14) 比率 + 波动率聚类（可加入 iCustom() 调用底层 AI 模型）。
- **性能优化规范**：
  - 必须写入 `IsNewBar()` 判断，仅在 K 线走完（如 H1 级别）时触发计算，严禁在 `OnTick()` 内循环计算，避免 CPU 占满。
  - 必须在 `OnInit()` 集中申请指标句柄（Handle），在 `OnDeinit()` 释放，切忌在函数内反复调用。
- **输出**：`enum MarketState { TRENDING, RANGING }` + 置信度（0~100）。

### 2. 趋势行情执行模块
- **策略类型**：均线突破、通道突破、动量跟踪、趋势 EMA、突破回踩。
- **核心特点**：宽止损 + 趋势仓位 + 让利润奔跑。
- **MQL5 实现**：独立函数 `ExecuteTrendStrategy()`。

### 3. 震荡行情执行模块
- **策略类型**：均值回归、布林带突破、RSI 超买超卖、区间震荡突破。
- **核心特点**：紧止损 + 小仓位 + 高频交易。
- **MQL5 实现**：独立函数 `ExecuteRangingStrategy()`。

### 4. 入场出场逻辑模块（统一管理与平滑过渡）
- **功能**：统一处理两个模块的开仓、加仓、止损、止盈、仓位计算。
- **参数动态调整**：
  - 震荡市：止损紧（ATR × 0.8~1.2），仓位小（0.5%~1%）。
  - 趋势市：止损宽（ATR × 1.8~2.5），仓位较大（1%~1.5%）。
- **【核心补充】遗留仓位处理机制 (Position Handover)**：
  - 状态切换（如趋势转震荡）时，系统不再按照原策略开新仓，但需要对旧仓位进行**“降级管理”**。
  - **动作**：立刻将原趋势宽止损收紧，或激活激进的移动止盈（Trailing Stop），让遗留仓位平滑自然死亡或落袋出局，防止被剧烈洗盘打损。

### 5. 全局风控模块（最高优先级监控）
- **触发条件与机制**：
  - **熔断机制**：单日最大回撤 > 设定阈值 / 连续亏损次数达到上限 / 账户权益低于安全线。
  - **【核心补充】净敞口监控 (Net Exposure)**：监控多品种相关性风险（如同时做多 EURUSD 和 GBPUSD），限制全盘总敞口。
- **动作**：强制平仓 + 暂停交易 + 记录日志 + 发送通知。
- **MQL5 性能优化**：对订单状态的追踪摒弃 `OnTick()` 循环，改用原生 `OnTradeTransaction()` 事件精准捕捉成交、拒绝或平仓信号，提升执行效率。

## 四、核心机制设计（解决冲突关键）

### 1. 状态机 + 滞后过滤机制（必须实现）
- **最小切换间隔**：建议至少持续 **8~12 根 K 线** 才允许切换。
- **置信度阈值**：只有置信度 > 75% 时才允许切换。
- **滞后机制**：使用静态变量记录上一次状态和切换时间，避免市场刚开始转换时来回被锯齿割伤（Whipsaw）。

### 2. 优先级规则（严格执行）
1. **熔断模块**（最高优先级）→ 无论任何情况，熔断信号立即执行。
2. **行情判断模块** → 决定当前激活哪个执行模块。
3. **入场出场逻辑模块** → 最终执行交易。
4. **互斥运行** → 趋势和震荡执行模块在同一时间只能激活一个。

### 3. 仓位管理建议
- 震荡市：单笔风险 ≤ 0.5% ~ 1%
- 趋势市：单笔风险 ≤ 1% ~ 1.5%
- 总仓位极限：震荡市 ≤ 30%，趋势市 ≤ 60%

## 五、MQL5 机构级代码结构建议（推荐目录树）

```text
Experts/
└── JessieOBS/
    ├── JessieOBS.mq5                  ← 主文件（入口，统筹调度事件驱动）
    ├── Includes/
    │   ├── Defines.mqh                ← 全局枚举、宏定义 (如 enum MarketState)
    │   ├── MarketStateDetector.mqh    ← 行情判断模块 (只负责输出状态)
    │   ├── TrendStrategy.mqh          ← 趋势执行模块
    │   ├── RangingStrategy.mqh        ← 震荡执行模块
    │   ├── EntryExitManager.mqh       ← 入场出场逻辑 (包含仓位计算与遗留仓位接管)
    │   ├── RiskManager.mqh            ← 全局风控模块 (硬核熔断与敞口监控)
    │   └── StateMachine.mqh           ← 状态机 + 滞后过滤 (平滑过渡逻辑)
    ├── Inputs/
    │   └── Parameters.mqh             ← 所有 extern/input 参数分离，方便遗传算法优化
    ├── Indicators/                    ← (可选) 存放依赖的自定义 .ex5 指标文件
    └── Utils/                         
        ├── TradeWrapper.mqh           ← 封装 CTrade，处理重试机制和错误码 (如 Error 10004)
        └── Logger.mqh                 ← 统一日志输出，支持分级 (INFO, WARN, ERROR)
