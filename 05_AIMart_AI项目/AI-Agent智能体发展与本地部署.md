# AI Agent 智能体发展：工具调用能力与模型选择

## 核心要点
- 2025 年被广泛预测为"AI 智能体之年"，各主要 AI 厂商都在发力 Agent
- 本地部署跑 Agent 时，稠密模型（Dense Model）优于 MoE 混合专家模型——27B 稠密模型战胜了 397B 的 MoE 模型
- MCP 协议（Anthropic）与 Agent 接口（OpenAI）代表了两种生态路线
- Claude 在各 Agent 工具调用测试中从领先其他模型

## 关键洞察

### Agent 架构与工具调用
AI Agent 的核心理念是"大脑（AI 大模型）+ 双手（各种计算工具）"：
- 大脑负责理解任务、规划步骤
- 工具包括搜索、代码执行、文件编辑等
- MCP 协议让工具和模型以标准化方式连接
- Agent SDK 支持多智能体协同

### 本地部署模型选择：稠密 > MoE
经过 15 个场景、12 个工具的系统测试，结果出人意料：
- 27B 稠密模型（全部参数参与计算）全数通过所有测试
- 397B MoE 模型（参数看似很大但每次只激活一部分）挂掉 2 个任务
- 所有 MoE 模型集体挂掉的任务是"搜索某个数据并计算百分比"——模型调用工具后不相信工具返回的数据，调用自己记忆中的大概数字
- 原因：稠密模型注意力机制占比更大，上下文跟踪能力天然更强
- Claude 是当前主流前援模型中唯一使用稠密架构的（GPT、Gemini 等都已转 MoE），这可能是 Claude 在 Agent 领域最强的结构性原因

### "智能体"的设计哲学
来自 Claude Code 设计团队的总结，适用于任何 Agent 搭建：
- **工具要少而精**：Claude Code 官方约 20 个工具，团队觉得都太多
- **不要替 Agent 决定该看什么**：给它搜索工具和入口文件，让它自己挖
- **子代理代替加工具**：某些功能放在子代理中，需要时才激活，而非永久占用上下文
- **定期审视工具集**：3 个月前模型需要的工具，现在可能已是限制
