总体目标：
让 AIMart 生成的执行包自带 Codex 无人值守启动能力，使用户下载生成包后，不需要反复批准普通命令，也能让 Codex 在安全边界内连续执行任务、测试、构建、收尾和生成报告。

v0.2.0 必须实现：

1. Codex Autonomous Run Profile
   - 在生成的执行包中增加：
     - agent_adapters/codex/CODEX_AUTONOMOUS_PROMPT.md
     - agent_adapters/codex/CODEX_AUTONOMOUS_RUNBOOK.md
     - agent_adapters/codex/run-codex-autonomous.ps1
     - agent_adapters/codex/run-codex-supervised.ps1
     - agent_adapters/codex/run-codex-autonomous.sh
     - agent_adapters/codex/run-codex-supervised.sh
   - autonomous 脚本使用 workspace-write + approval never 或当前 Codex 版本支持的等效参数。
   - supervised 脚本使用 workspace-write + on-request。

2. Runtime Command Policy 文件
   - 在生成执行包中增加或强化：
     - runtime/SAFE_COMMANDS.md
     - runtime/DENIED_COMMANDS.md
     - runtime/APPROVAL_QUEUE.md
     - runtime/AUTONOMOUS_EXECUTION_POLICY.md
   - 明确允许自动执行的普通命令：安装项目依赖、lint、test、build、finalize、读取 ZIP entries、本地端口查询、写入当前版本 release。
   - 明确禁止自动执行的高风险命令：git push、删除历史 release、读取密钥、生产部署、真实数据库迁移、云资源创建或删除。

3. Web UI 配置项
   - 增加执行模式选择：
     - Supervised Mode
     - Autonomous Mode
   - 默认可以仍为 Supervised Mode，但用户选择 Autonomous Mode 时，生成包应包含无人值守脚本和说明。
   - UI 文案必须区分 source release ZIP 与 generated execution-pack ZIP。

4. 文档更新
   - 更新 docs/README.md、docs/RUN_APP.md、docs/SECURITY_AND_PERMISSIONS.md 的生成模板。
   - 新增说明：如何启动 Codex 无人值守模式、如何查看日志、如何处理 APPROVAL_QUEUE。
   - 更新 README / RELEASE_NOTES / FINAL_DELIVERY_CHECK 或生成 v0.2.0 专用交付文档。

5. 测试
   - 更新执行包结构测试，确认 generated execution-pack ZIP 包含新增 Codex autonomous files。
   - 测试 runtime policy 文件存在。
   - 如果现有测试架构允许，测试 UI execution mode 字段会影响生成结果。
   - 保证已有测试继续通过。

6. 版本与交付
   - package.json 版本更新为 0.2.0。
   - UI 版本显示更新为 v0.2.0。
   - 生成：
     - V0.2.0_IMPLEMENTATION_REPORT.md

连续执行规则：
1. 不要在普通命令前等待用户。
