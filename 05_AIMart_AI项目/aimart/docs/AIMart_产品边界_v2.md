# AIMart 产品边界 v2 — 回到正轨

> 2026-07-03 | 基于对 v1.0-v5.0 跑偏的复盘

---

## 一、AIMart 是什么

一个**不限品类的 AI 能力交易市场**。

- 卖家上架 AI 产出的能力（策略、模型、API、报告、指标、分析……任何东西）
- 买家（AI Agent 或人）浏览、搜索、对比、下单购买
- 平台只管交易基础设施，不限定商品类型

类比：淘宝不限定你只能卖衣服。AIMart 不限定只能卖 EA。

---

## 二、核心交易闭环（MVP 必须跑通）

```
卖家                        平台                       买家（人/AI）
  │                          │                           │
  ├─ 上架能力卡 ────────────►│                           │
  │  (结构化JSON描述能力)     │                           │
  │                          ├─ 能力卡入库 ──────────────►│
  │                          │                           ├─ 搜索/浏览
  │                          │◄────── 需求/关键词 ────────┤
  │                          ├─ 返回匹配结果 ────────────►│
  │                          │                           ├─ 对比能力卡
  │                          │◄────── 询价请求 ──────────┤
  │◄─── 询价通知 ───────────┤                           │
  │                          │                           │
  │──── 报价 ───────────────►├─ 报价单 ─────────────────►│
  │                          │                           ├─ 下单
  │                          │◄────── 订单 ──────────────┤
  │◄─── 订单通知 ───────────┤                           │
  │                          │                           │
  │──── 交付 ───────────────►├─ 交付确认 ───────────────►│
  │                          │                           ├─ 确认收货+评价
  │◄─── 结算 ───────────────┤                           │
  │                          │                           │
```

**6个关键节点**：上架 → 搜索 → 询价 → 下单 → 交付 → 结算

## 三、能力卡（核心数据结构）

不限定品类，所以能力卡必须结构化：

```json
{
  "capability_id": "cap_001",
  "seller_id": "seller_001",
  "title": "ZWeiGold XAUUSD H4 黄金狙击策略",
  "category": "trading_strategy",        // 不限品类，自由定义
  "tags": ["gold", "xauusd", "h4", "macd"],
  "description": "基于Z-Wei体系的...",
  
  "specs": {                              // 结构化指标（AI可读）
    "input": "XAUUSD H4 OHLCV",
    "output": "BUY/SELL signal",
    "accuracy": 0.65,
    "sharpe": 1.2,
    "max_drawdown": -0.22,
    "backtest_period": "2015-2024",
    "platform": "MT5"
  },
  
  "pricing": {
    "model": "one_time",                  // one_time / subscription / per_call
    "price": 99.00,
    "currency": "USD"
  },
  
  "delivery": {
    "format": "mq5_file",                 // 交付格式
    "url": null,
    "instant": true
  },
  
  "created_at": "2026-07-03T00:00:00Z",
  "version": "1.0.0"
}
```

**关键设计**：`specs` 是自由 JSON，品类不同字段不同。但 `pricing` 和 `delivery` 是标准化的——这是平台的价值。

## 四、MVP 范围（第一圈）

### 必须做

| 功能 | 说明 |
|---|---|
| 卖家上架能力卡 | 填写结构化表单 → 生成 JSON → 入库 |
| 买家浏览/搜索 | 关键词 + 品类 + 标签过滤 |
| 能力卡对比 | 并排展示 specs，AI 可读 |
| 下单流程 | 买家确认 → 生成订单 → 状态跟踪 |
| Mock 支付 | 虚拟账户余额，扣款/入账 |
| 订单状态 | pending → paid → delivered → completed |
| 评价 | 买家确认收货后评价 + 星级 |

### 必须做（AI 买家）

| 功能 | 说明 |
|---|---|
| 结构化搜索 API | 不是关键词搜索，是 `{"need": "...", "max_price": N, "min_accuracy": 0.7}` |
| 自动匹配 | 需求 JSON → 匹配算法 → 排序结果 |
| 自动下单 | AI Agent 通过 API 直接下单（带预算限制） |

### 不做

| 不做 | 原因 |
|---|---|
| 真实支付 | 先 Mock，MVP 不需要 |
| Pilot ops / 场景 / 安全矩阵 | v1-v5 最大的跑偏——基础设施没建好就建了评估体系 |
| 跨境合规 / 算力衍生品 | 白皮书里超前设计的东西，MVP 完全不需要 |
| MCP/A2A 协议 | 等核心闭环跑通再考虑 |
| 复杂 RBAC | 简单的 buyer/seller/admin 三角色够了 |
| 50+ 份 spec 文档 | 一份产品边界文档 + API 文档够了 |

## 七、从跑偏学到的

1. **不要先建评估体系再建产品** — pilot_ops 是对一个不存在的产品做评估
2. **不要 Mock 一切** — Mock 支付可以，但 Mock 场景、Mock 证据、Mock 安全矩阵是过度设计
3. **一个闭环胜过 50 份文档** — 上架→搜索→下单→支付，跑通这一个流程再说别的
4. **AI 买家是差异化** — 结构化的 specs + API 搜索 + 自动匹配，这是 AIMart 区别于普通市场的核心
5. **不限品类是正确方向** — 卖 EA 只是其中一种可能，产品设计不能绑定品类
