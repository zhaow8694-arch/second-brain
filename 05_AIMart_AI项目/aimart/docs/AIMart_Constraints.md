## 一、交易规则

### 1.1 商品上架规则

| 规则 ID | 规则内容 | 适用对象 | 违规后果 |
|---------|---------|---------|---------|
| TR-001 | 上架商品必须提供 AgentCard（机器可读能力声明） | Provider | 拒绝上架 |
| TR-002 | 上架商品必须提供至少一项基准测试结果 | Provider | 拒绝上架 |
| TR-003 | 能力声明中的性能指标不得高于基准测试结果的 110%（防止过度承诺） | Provider | 自动降级声明或拒绝上架 |
| TR-004 | 定价必须明确（按量/按时/订阅/免费），不得设置隐性费用 | Provider | 下架 + 保证金扣除 |
| TR-005 | 模型类商品必须声明支持的输入/输出格式和版本兼容性 | Provider | 拒绝上架 |
| TR-006 | 技能类商品必须通过沙箱安全扫描（无恶意代码、无数据外泄行为） | Provider | 拒绝上架 |
| TR-007 | 专家类商品必须声明知识库更新频率和最后更新时间 | Provider | 拒绝上架 |
| TR-008 | 算力类商品必须声明可用性承诺（SLA）和最大并发数 | Provider | 拒绝上架 |
| TR-009 | 商品版本更新必须重新提交验证，验证期间旧版本可继续服务 | Provider | 旧版本自动下架 |
| TR-010 | 开源商品可免费上架；商业商品需缴纳保证金（详见定价章节） | Provider | 拒绝上架 |

### 1.2 交易流程规则

| 规则 ID | 规则内容 | 适用阶段 |
|---------|---------|---------|
| TR-011 | Agent 必须通过搜索域发起能力需求，不得绕过搜索直接调用 | 搜索 |
| TR-012 | 搜索结果最多返回 20 条匹配项，按匹配度+信任评分排序 | 搜索 |
| TR-013 | Agent 可对搜索结果中的商品发起试用（每个商品每日最多 3 次） | 试用 |
| TR-014 | 试用调用受沙箱隔离，输入规模限制为正常的 10%，调用次数上限 5 次 | 试用 |
| TR-015 | 试用结果以结构化数据返回 Agent，不含人类可读 UI | 试用 |
| TR-016 | 购买决策由 Agent 自主完成（在授权范围内），平台不干预决策 | 购买 |
| TR-017 | 订单创建后 30 秒内未完成支付自动过期 | 购买 |
| TR-018 | 每笔交易必须关联一个预算池，预算不足时交易拒绝 | 支付 |
| TR-019 | 担保交易模式下，资金在效果确认前冻结于托管账户 | 支付 |
| TR-020 | 效果回传窗口期为交付后 24 小时，超时未回传视为"默认达标" | 回传 |
| TR-021 | Agent 必须回传结构化效果数据（不可只回传"好"或"差"） | 回传 |
| TR-022 | 争议必须在效果回传后 72 小时内发起，超时不再受理 | 争议 |
| TR-023 | 争议期间相关资金持续冻结，直至仲裁完成 | 争议 |
| TR-024 | 仲裁由平台执行，7 个工作日内给出裁决 | 争议 |

### 1.3 四类商品的特殊交易规则

#### 模型类

```
TR-MODEL-001: 模型 API 调用按 Token 计费时，必须提供 Token 计数器供 Agent 实时查询
TR-MODEL-002: 模型权重下载为一次性购买，下载后不支持退款（除非文件损坏）
TR-MODEL-003: 模型版本变更时，已订阅的 Agent 将收到版本变更通知，7 天内可选择是否升级
TR-MODEL-004: 模型推理延迟超过声明值 200% 时，Agent 可发起自动争议
```

#### 技能类

```
TR-SKILL-001: 技能代码必须在沙箱中运行，首次使用前强制沙箱验证
TR-SKILL-002: 技能运行时的资源消耗（CPU/内存/网络）必须声明上限，超出自动终止
TR-SKILL-003: 技能不得访问 Agent 的上下文数据，除非 Agent 显式授权
TR-SKILL-004: 技能订阅制商品，Agent 可随时取消订阅，已消费部分不退
```

#### 专家类

```
TR-EXPERT-001: 专家必须声明知识库覆盖的领域范围和边界（声明外领域不保证质量）
TR-EXPERT-002: 专家知识库更新频率不得低于声明值，否则信任评分自动下调
TR-EXPERT-003: 专家咨询按次计费时，单次咨询的输入/输出 Token 上限必须声明
TR-EXPERT-004: 专家回答与领域标准的一致性偏差超过 20% 时，Agent 可发起争议
```

#### 算力类

```
TR-COMPUTE-001: 算力按时计费时，最小计费单位为 1 分钟
TR-COMPUTE-002: 算力租用期间，可用性低于 SLA 承诺时按比例退款
TR-COMPUTE-003: 算力租用可设置自动续期，但续期需在预算池额度内
TR-COMPUTE-004: 算力提供方因故障中断服务超过 15 分钟，自动触发赔偿
```

### 2.2 分层授权规则

| 层级 | 金额范围（CNY） | 授权方式 | 通知机制 | 超限处理 |
|------|---------------|---------|---------|---------|
| L0-全自动 | ≤ 0.01/次 | Agent 自主 | 无 | 记录日志 |
| L1-事后通知 | 0.01 - 1.00/次 | Agent 自主 | 交易完成后 5 分钟内通知 Owner | 连续 10 次同卖家触发复核 |
| L2-事前审批 | 1.00 - 100.00/次 | 需 Owner 授权 | 实时推送给 Owner | 30 分钟未审批自动拒绝 |
| L3-人工确认 | > 100.00/次 | Owner 亲自确认 | 实时推送 + 短信/邮件 | 1 小时未确认自动拒绝 |

### 2.3 预算异常规则

| 异常类型 | 判定条件 | 自动响应 |
|---------|---------|---------|
| 突发性消费 | 1 小时内消费超过日限额的 50% | 暂停该 Agent 交易 + 通知 Owner |
| 高频微支付 | 1 分钟内超过 100 笔 L0 交易 | 限速至 10 笔/分钟 + 通知 Owner |
| 预算耗尽 | 余额 < 单笔最低限额 | 暂停所有 Agent 交易 + 通知 Owner |
| 异常卖家 | 同一 Agent 80% 以上支出流向单一卖家 | 触发卖家审查 + 通知 Owner |
| 非工作时间大额 | L2/L3 交易发生在非工作时段 | 提升授权级别（L2→L3, L3→人工复核） |

## 三、风险管理

### 3.1 风险分类与等级

| 风险 ID | 风险类别 | 风险描述 | 等级 | 概率 | 影响 |
|---------|---------|---------|------|------|------|
| R-001 | 安全 | 恶意技能窃取 Agent 上下文数据 | P1-严重 | 中 | 数据泄露、法律风险 |
| R-002 | 安全 | 模型投毒导致 Agent 输出被操纵 | P1-严重 | 低 | 业务决策错误、声誉损失 |
| R-003 | 金融 | Agent 被诱导进行非预期消费 | P2-高 | 中 | 财务损失、用户信任下降 |
| R-004 | 金融 | 卖家虚报能力导致买方损失 | P2-高 | 中 | 交易纠纷、平台声誉 |
| R-005 | 运营 | 算力供应不足导致服务中断 | P2-高 | 高 | 交易失败、SLA 违约 |
| R-006 | 运营 | 协议碎片化导致集成成本失控 | P3-中 | 高 | 开发效率下降 |
| R-007 | 合规 | AI 自主交易的法律主体争议 | P2-高 | 中 | 监管处罚、业务暂停 |
| R-008 | 合规 | 跨境数据传输违反本地法规 | P1-严重 | 中 | 法律风险、罚款 |
| R-009 | 信任 | 评价体系被刷分操纵 | P3-中 | 中 | 信任评分失效 |
| R-010 | 技术 | Agent 决策不稳健导致大量无效交易 | P3-中 | 高 | 系统负载、用户体验差 |

### 3.2 风险应对措施

#### R-001 恶意技能数据窃取

```
预防：
  - 技能上架前强制沙箱安全扫描
  - 技能运行时网络隔离（仅允许与声明的外部服务通信）
  - Agent 上下文数据默认不传递给技能，需显式授权

检测：
  - 运行时行为监控：检测异常网络请求、异常数据访问
  - Agent 消费模式分析：检测被诱导消费的模式

响应：
  - 自动终止恶意技能运行
  - 冻结卖家账户
  - 通知所有使用该技能的 Agent Owner
  - 启动安全审计
```

#### R-003 Agent 被诱导消费

```
预防：
  - 分层授权机制（L0-L3）
  - 单卖家消费集中度监控
  - 卖家能力声明验证（不得超过基准测试 110%）

检测：
  - 消费模式异常检测
  - Agent 决策路径审计

响应：
  - 触发异常规则自动暂停交易
  - 通知 Owner 确认
  - 对诱导消费的卖家进行处罚
```

#### R-004 卖家虚报能力

```
预防：
  - 基准测试结果强制提交
  - 能力声明自动校验（声明值 vs 基准测试值）
  - 担保交易机制

检测：
  - Agent 效果回传与卖家声明的偏差分析
  - 偏差超过 20% 自动触发调查

响应：
  - 信任评分自动下调
  - 严重虚报：商品下架 + 保证金扣除
  - 连续 3 次虚报：卖家封禁
```

## 四、安全约束

### 4.1 身份与认证

| 约束 ID | 约束内容 | 适用范围 |
|---------|---------|---------|
| SEC-001 | 所有 API 调用必须携带有效凭证（API Key / OAuth2 Token / mTLS） | 全部 |
| SEC-002 | Agent 凭证有效期不超过 1 小时，支持自动刷新 | Agent |
| SEC-003 | Owner 操作需多因素认证（MFA） | Owner |
| SEC-004 | 敏感操作（修改预算、审批大额交易、暂停 Agent）需二次确认 | Owner |
| SEC-005 | API Key 不得硬编码，必须通过安全存储服务获取 | Agent / Provider |
| SEC-006 | 所有凭证轮换周期不超过 90 天 | 全部 |

### 4.2 数据安全

| 约束 ID | 约束内容 | 适用范围 |
|---------|---------|---------|
| SEC-007 | Agent 上下文数据默认不传递给卖家，传递需 Agent 显式授权 | Agent ↔ Provider |
| SEC-008 | 传递给技能的上下文数据必须标记敏感度级别（public / internal / confidential / restricted） | Agent → Skill |
| SEC-009 | 交易数据加密传输（TLS 1.3+） | 全部 |
| SEC-010 | 静态数据加密存储（AES-256） | 平台存储 |
| SEC-011 | 担保交易中的冻结资金存储在独立托管账户，平台不可动用 | 支付域 |
| SEC-012 | 审计日志不可篡改（追加写入 + 哈希链校验） | 审计域 |
| SEC-013 | 数据跨境传输必须符合源和目标法域的法规 | 跨境场景 |
| SEC-014 | Agent 的效果回传数据不得包含原始输入内容，只含评估指标 | 信任域 |

### 4.3 沙箱安全

| 约束 ID | 约束内容 | 适用范围 |
|---------|---------|---------|
| SEC-015 | 技能类商品首次运行必须在沙箱中执行 | 技能 |
| SEC-016 | 沙箱网络隔离：仅允许与白名单中的外部服务通信 | 技能 |
| SEC-017 | 沙箱资源限制：CPU ≤ 2 核，内存 ≤ 4GB，运行时间 ≤ 60 秒/次 | 技能 |
| SEC-018 | 沙箱文件系统只读挂载，禁止写入宿主机 | 技能 |
| SEC-019 | 沙箱运行日志独立记录，包含所有系统调用 | 技能 |
| SEC-020 | 沙箱中检测到异常行为（网络外连、文件访问越界）立即终止 | 技能 |

## 五、SLA（服务等级协议）

### 5.1 平台 SLA

| 指标 | 目标值 | 测量方式 | 未达标补偿 |
|------|--------|---------|-----------|
| 平台可用性 | ≥ 99.9%（月度） | 成功请求 / 总请求 | 可用性 < 99.9%：当月平台服务费减免 10% |
| 搜索响应时间 | P99 < 500ms | 从请求到返回结果的时间 | 超时请求不计费 |
| 订单创建延迟 | P99 < 200ms | 从请求到订单确认的时间 | 超时订单自动取消，不扣款 |
| 支付结算延迟（x402） | P99 < 5s | 从支付请求到链上确认的时间 | 超时免收该笔交易佣金 |
| 支付结算延迟（ACP） | P99 < 30s | 从支付请求到结算确认的时间 | 超时免收该笔交易佣金 |
| 争议仲裁时间 | ≤ 7 个工作日 | 从争议创建到裁决的时间 | 超时平台承担争议金额 |
| 数据持久性 | ≥ 99.999% | 数据丢失事件 | 全额赔偿直接损失 |

### 5.2 卖家 SLA（必须声明）

| 商品类型 | 必须声明的 SLA 指标 | 允许范围 |
|---------|-------------------|---------|
| 模型 | 推理延迟 P99 | 10ms - 30s |
| 模型 | 可用性 | ≥ 99.5% |
| 模型 | 输出一致性（同输入同输出概率） | ≥ 95% |
| 技能 | 任务完成率 | ≥ 80% |
| 技能 | 执行时间 P99 | 1s - 300s |
| 技能 | 资源消耗上限 | CPU/内存/网络 |
| 专家 | 领域知识准确性 | ≥ 85% |
| 专家 | 回答一致性 | ≥ 90% |
| 专家 | 知识库更新频率 | ≥ 声明值 |
| 算力 | 实例可用性 | ≥ 99.0% |
| 算力 | 启动延迟 | ≤ 5 分钟 |
| 算力 | 最大并发数 | ≥ 声明值 |

### 5.3 SLA 违约处理

```
卖家 SLA 违约处理流程：

1. 自动检测：平台监控系统检测到 SLA 指标低于承诺值
2. 确认：系统自动确认违约事实（排除买方原因）
3. 处理：
   a. 单次违约：向买方退还该笔交易费用 + 卖家信任评分 -5
   b. 月累计 3 次违约：商品标记"SLA 不稳定"标签 + 信任评分 -15
   c. 月累计 5 次违约：商品自动下架 + 卖家保证金扣除
4. 通知：违约信息通知买方 Owner 和卖家
5. 申诉：卖家可在 3 个工作日内申诉，平台审核后决定是否恢复
```

### 6.3 定价变更规则

```
PRICING-001: 卖家调低价格即时生效
```
