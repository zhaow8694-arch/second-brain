### 1.1 电商进化史：三次范式迁移

电子商务的发展可以划分为三次根本性的范式迁移，每一次都重新定义了"谁在买"和"怎么买"。

**第一次迁移（2000年代）：货架数字化。** 亚马逊、淘宝、eBay 的核心贡献不是发明了交易，而是把物理货架搬到了网页上。买家还是人，商品还是商品，只是"看"的方式从线下变成了线上。这一阶段的效率提升主要来自信息透明度的增加——消费者可以比价、看评价、跨店选择，而不必亲身跑遍每一家商店。

**第二次迁移（2010年代）：交易即时化。** 移动支付（支付宝、微信支付、Apple Pay）和物流基础设施（当日达、次日达）的成熟，将"看到商品"和"完成交易"之间的时间差压缩到了几秒钟。关键变量不再是信息获取，而是决策执行的速度和摩擦。当支付变成一个指纹、物流变成一个承诺，消费行为从"计划性购买"大量转向"冲动性购买"。

**第三次迁移（2026年—）：决策自动化。** 我们正在经历的，是一场更根本的变化——不是"买得更快"，而是"谁来买"。当 AI Agent 能够理解用户意图、搜索商品、比较选项、协商价格并完成支付，购物的决策主体就从人类转移到了 AI。这不是前两次迁移的量变延续，而是质变：买家从人变成了 Agent，交易从"人决策+人执行"变成了"人授权+AI 执行"，并正在走向"AI 自主决策+AI 自主执行"。

麦肯锡预测，到 2030 年，代理型商务（Agentic Commerce）将捕获高达 1 万亿美元的美国零售收入，占全部在线销售的三分之一（McKinsey, 2025）。摩根士丹利的研究则估计，AI 购物代理到 2030 年将驱动 1900 亿至 3850 亿美元的美国电商支出（Morgan Stanley Research）。Mordor Intelligence 的数据更为激进：全球代理型 AI 在零售/电商市场的规模将从 2025 年的 467.4 亿美元增长到 2030 年的 1751.1 亿美元，年复合增长率达 30.2%。

这些数字传递的信号很明确：**AI 正在成为经济活动中一个独立的、有购买力的参与者。** 但问题是——它去哪买？

### 1.2 一个被忽视的买家：AI Agent

2025 至 2026 年间，一组数据揭示了 AI Agent 从"辅助工具"向"自主经济主体"跃迁的速度：

- **企业部署率飙升**：79% 的美国企业高管报告已在组织中部署 AI Agent（PwC, 2025年5月）；62% 的组织正在实验 AI Agent，23% 已进入规模化部署阶段（McKinsey State of AI, 2025）。
- **流量爆发式增长**：AI Agent 对零售网站的流量同比增长 1300%（ChannelEngine 2026 市场报告）；Shopify 平台上 AI 驱动的流量自 2025 年 1 月增长 8 倍，AI 驱动的订单增长 15 倍。
- **投资热情空前**：2025 年 Agentic AI 领域融资总额达 64.2 亿美元，创该领域历史新高，占十年总融资的 27%；2026 年前 4 个月融资 26.6 亿美元，同比暴增 144%（AgentMarketCap, 2026）。
- **ROI 已被验证**：88% 的零售商报告 AI Agent 实施的 ROI 为正，62% 预计首年 ROI 超 100%（Google Cloud, 2025）；企业部署 AI Agent 的平均 ROI 达 171%（Futurum Research, 2026）。

这些数据的含义不只是"AI Agent 很火"。更深层的事实是：**AI Agent 正在从"帮人做事"进化为"自己做事"。** 当一个 Agent 发现自己的推理能力不足以处理法律合同审查时，它需要找一个法律专家模型；当它缺少某个领域的操作技能时，它需要下载一个技能包；当它的本地算力不足以完成大模型推理时，它需要临时租用 GPU。

**这是一个真实存在的、正在快速增长的购买需求——但购买的主体不是人，而是 AI。**

### 1.3 现有 AI 平台的根本局限

当前的 AI 平台和模型仓库——无论是 HuggingFace、ModelScope，还是 Replicate、Together AI——在设计之初都有一个隐含假设：**浏览者和决策者是人类。**

以 HuggingFace 为例，它是目前最成功的 AI 开放平台：估值 45 亿美元，1300 万用户，200 万+模型，2024 年收入 1.3 亿美元且 2025 年已实现盈利。它的核心资产是"模型分发网络 + 协作入口 + 身份与声誉系统 + 发现机制"——这一切都是为人设计的。模型卡用自然语言描述能力，搜索需要人输入关键词，比较需要人阅读文档，决策需要人综合判断。

这并非 HuggingFace 的设计失误——它的使命就是服务人类开发者。但当我们把目光转向 AI Agent 作为买家时，现有平台缺失了三个关键能力：

**1. 机器可读的商品描述。** 现有平台的模型/技能描述是自然语言文本，面向人类阅读理解。AI Agent 需要的是结构化的能力声明——支持什么任务、精度多少、延迟多少、价格多少、兼容什么接口——用标准化的 Schema 表达，而非营销文案。

**2. AI 自主搜索与匹配接口。** 人类在 HuggingFace 上搜模型，靠的是关键词和排序。AI Agent 需要的是一种协议级的搜索能力：说出自己的需求（"我需要一个能做中文法律合同审查的专家模型，延迟<2s，价格<0.01元/次"），市场返回精确匹配的商品列表。

**3. 自动化支付与结算。** 人类购买 API 额度，需要注册账号、绑定信用卡、确认支付。AI Agent 需要的是毫秒级的自动结算：发现需求 → 匹配商品 → 调用服务 → 效果确认 → 自动扣款，全链路无需人类介入。

这三层缺失，构成了 AIMart 要填补的核心空白。不是替代 HuggingFace，而是在 HuggingFace 之上（或旁边），建设一个 **AI-first** 的交易层——让 AI Agent 不仅能"看到"能力，更能"买到"能力。

## 二、AIMart 定义——平台不做产品，只做 AI 世界的交易基础设施

### 2.1 核心定位

AIMart 的核心定位可以用一句话概括：**AI 能力的淘宝，AI Agent 的交易所。**

与淘宝一样，AIMart 只做平台，不做产品。平台不训练模型、不开发技能、不养专家、不建算力中心——这些全部由卖家提供。平台的价值在于：让买家（AI Agent）和卖家（能力提供方）以最高效率匹配、交易、结算。

这个定位的本质是一种**双边市场**。与所有双边市场一样，核心飞轮是：卖家多 → 商品丰富 → 买家愿意来 → 买家多 → 卖家愿意上架 → 卖家更多。而飞轮的启动点，是降低双方的核心摩擦——对买家来说，是"找到合适能力的摩擦"；对卖家来说，是"让自己的能力被发现的摩擦"。

与淘宝不同的是，AIMart 的买家主要不是人类，而是 AI Agent。这意味着整个平台的设计哲学必须从"以人为本"翻转为"以 AI 为本"：

| 设计维度 | 人类市场 | AIMart |
|---------|---------|--------|
| 商品描述 | 自然语言文案+图片 | 结构化能力声明（JSON Schema） |
| 搜索方式 | 关键词+筛选器 | 意图描述→能力匹配 |
| 决策方式 | 人类综合判断 | AI 评分+试用验证 |
| 支付方式 | 注册→绑卡→确认 | M2M 自动结算 |
| 评价方式 | 文字评论+星级 | 结构化效果回传+质量指标 |
| 客服方式 | 人工/聊天机器人 | Agent 间协商（A2A） |

### 2.2 四类商品定义与差异

AIMart 交易的四类商品，本质上是 AI Agent 在执行任务时可能遇到的四类"能力缺口"：

**模型（Models）**——推理能力的购买。当一个 Agent 发现当前使用的模型在数学推理上不够强，它可以在市场上找到一个数学推理专长模型，按 Token 或按次付费调用。交付方式以 API 调用为主，权重下载为辅。定价模型以按量计费为主。核心挑战在于版本管理与兼容性——同一模型的不同版本可能行为差异巨大，Agent 需要精确知道它调用的是哪个版本、在哪个基准测试上表现如何。

**技能（Skills）**——操作能力的购买。技能是封装好的、可执行的代码包或配置文件，让 Agent 获得某个领域的操作能力——比如"生成 PPT"、"操作 Excel"、"调用特定 API"。交付方式是代码包下载或在线加载，定价可以是按次、按订阅或免费。核心挑战是安全性：技能可能包含恶意代码（类似 HuggingFace 上已发现的 35.2 万个可疑模型问题），需要沙箱运行和严格验证。

**专家（Experts）**——知识能力的购买。专家是领域微调模型与知识库的组合体，相当于"AI 可以请教的领域顾问"——法律专家、医疗专家、金融专家。交付方式以 API 调用为主，定价按咨询次数或按 Token。核心挑战是知识时效性（法律条文更新了，专家知道吗？）和专业性验证（这个"法律专家"真的懂合同法吗？）。

**算力（Compute）**——执行能力的购买。当 Agent 本地资源不足以运行大模型推理或训练时，需要临时扩容。交付方式是 GPU 实例或推理端点，定价按时或按量。核心挑战是弹性调度（高峰时能租到吗？）和可用性（高端 GPU 出租率已超 90%，供给紧张）。

| 商品类型 | 交付方式 | 定价模型 | 买家需求场景 | 核心挑战 |
|---------|---------|---------|------------|---------|
| 模型 | API调用/权重下载 | 按Token/按次 | 推理能力不足时升级 | 版本管理、兼容性 |
| 技能 | 代码包/配置文件 | 按次/订阅 | 缺少某领域能力时加装 | 安全性（技能可能有毒） |
| 专家 | 领域微调模型+知识库 | 按咨询/按Token | 遇到专业问题时咨询 | 知识时效性、专业性验证 |
| 算力 | GPU实例/推理端点 | 按时/按量 | 本地资源不足时扩容 | 弹性调度、可用性 |

### 2.3 与现有平台的本质区别

理解 AIMart 与现有平台区别的关键，不在于"卖什么"（商品类型有重叠），而在于"卖给谁"和"怎么卖"。

HuggingFace 卖模型和推理服务，但它卖给人的方式是：人在网页上浏览模型卡、阅读文档、选择模型、注册账号、获取 API Key、调用模型。整个过程的关键决策节点都需要人类参与。

AIMart 要做的是：AI Agent 在执行任务时发现能力缺口 → 自主搜索匹配 → 自主试用评估 → 自主决策购买 → 自动结算 → 获得能力继续任务。整个过程的关键决策节点可以零人类参与。

这不是对 HuggingFace 的否定，而是一层新的基础设施。HuggingFace 是模型仓库和开发者社区，AIMart 是 AI Agent 的交易层。HuggingFace 上的模型可以同时上架到 AIMart——就像工厂的产品可以同时放在仓库里和淘宝店铺里。区别在于，淘宝店铺是 AI 自己逛的。

## 三、技术架构——七层协议栈如何支撑 AIMart

### 3.1 当前 AI 商务协议全景

2025 至 2026 年间，AI 商务协议迎来了爆发式增长。七大协议从不同层面定义了 AI Agent 如何发现商品、完成交易、支付结算和协作配合：

**MCP（Model Context Protocol）**——连接层。Anthropic 于 2024 年 11 月发布，是 AI 到服务连接的事实标准。它定义了 AI 模型如何以标准化方式访问外部数据源和工具——就像 USB 标准之于外设连接。采纳速度极快：OpenAI 于 2025 年 3 月采纳，Google、微软、Shopify 相继跟进。2025 年夏天，Shopify 在所有店铺上激活了默认 MCP 端点，使数百万商户即刻对 MCP 兼容的 AI Agent 可见。MCP 在 AIMart 中的角色是**商品数据的接入层**——卖家通过 MCP Server 暴露自己的能力描述、定价、接口规范。

**UCP（Universal Commerce Protocol）**——商务旅程层。Google 与 Shopify 于 2025 年 1 月联合发布，覆盖从商品发现到购买到售后的完整购物旅程。UCP 定义了商品数据、优惠、库存、订单管理、物流追踪、退货和客服交互的标准化 Schema。超过 20 家合作伙伴，包括 Target、Walmart、Best Buy、Visa、Mastercard、Stripe 等。在 AIMart 中，UCP 可以作为**交易流程的编排层**——定义 Agent 从发现能力到完成购买的标准化步骤。

**ACP（Agentic Commerce Protocol）**——支付层。OpenAI 与 Stripe 于 2025 年 9 月联合发布，核心创新是共享支付令牌（Shared Payment Tokens, SPTs）。SPT 是代币化的支付工具，AI Agent 用它代替用户发起交易——限特定卖家、有时间金额上限、永不暴露底层支付凭证。已在 ChatGPT 的 Instant Checkout 功能中上线，Etsy、URBN 等品牌已采纳。在 AIMart 中，ACP 解决的是**AI 代理人类付费的场景**。

**A2A（Agent-to-Agent Protocol）**——协作层。Google 于 2025 年 4 月发布，定义了 AI Agent 之间如何通信和协作。核心概念是 Agent Card（JSON 格式的代理能力描述）和任务生命周期管理。150+ 组织支持，由 Linux 基金会治理。在 AIMart 中，A2A 解决的是**Agent 与 Agent 之间的协商**——买方 Agent 与卖方 Agent 谈判价格、确认规格、协调交付。

**x402**——M2M 微支付层。Coinbase 与 Cloudflare 于 2025 年 5 月联合发布，重新激活了 HTTP 402（Payment Required）状态码，实现机器对机器的自动化微支付结算。三阶段工作流：服务端返回 402 报价 → AI Agent 离线签名支付指令 → Facilitator 验证并完成链上结算。AI Agent 只需持有 USDC 等稳定币即可完成支付，无需持有 ETH 等 Gas 代币。到 2025 年 10-11 月，月交易量已达 2933 万美元、6313 万笔。在 AIMart 中，x402 解决的是**高频低值的 M2M 微支付**——比如每次 API 调用 0.001 元的自动结算。

**AP2（Agent Payments Protocol）**——支付基础设施层。Google 与 Coinbase 于 2025 年 9 月发布，定义了加密签名的支付授权框架，确保 AI Agent 的支付行为可验证、可追溯、可审计。

**MPP（Machine Payments Protocol）**——支付基础设施层。Stripe 于 2026 年 3 月发布，是 AI Agent 支付的开放标准，支持稳定币、信用卡、先买后付等多种支付方式。

### 3.2 AIMart 协议栈设计

七大协议并非竞争关系，而是分别覆盖 AI 商务栈的不同层级。但碎片化是真实存在的：一个想要全面覆盖所有 AI 入口的卖家需要同时支持四个以上协议，每个都需要理解规范、实现端点、维护合规。大型企业有专门团队可以承担，中小卖家则力不从心。

AIMart 的协议策略是**整合而非发明**：不创建新的协议，而是作为统一接入层，将现有协议整合为一个 AI Agent 可以"一站式"使用的完整栈。

```
┌─────────────────────────────────────────┐
│          AIMart 统一接入层               │
│   （AI Agent 的单一入口，屏蔽底层碎片）    │
├─────────────────────────────────────────┤
│  AI 能力搜索协议  │  AI 支付协议          │
│  (AIMart 核心创新)│  (ACP/x402/AP2/MPP)  │
├───────────────────┼─────────────────────┤
│  商品描述标准      │  交易流程编排         │
│  (AgentCard扩展)  │  (UCP)              │
├───────────────────┼─────────────────────┤
│  数据与工具接入    │  Agent间协作          │
│  (MCP)           │  (A2A)              │
└───────────────────┴─────────────────────┘
```

**AIMart 的核心创新是 AI 能力搜索协议**——定义 AI Agent 如何描述自己的需求、市场如何返回匹配结果。这是当前协议栈中缺失的关键一环：MCP 解决了"怎么连接"，UCP 解决了"怎么交易"，ACP/x402 解决了"怎么付钱"，但没有人解决"怎么找到"。

现有平台的搜索是面向人类的：输入关键词，返回排序结果列表，人类阅读后决策。AI Agent 需要的搜索是面向机器的：输入结构化的能力需求描述，返回精确匹配的能力列表（含价格、性能指标、可用性状态），Agent 可以直接基于返回结果做出购买决策。

### 3.3 AI 如何"逛"市场

AIMart 定义了 AI Agent 在市场上"逛街"的五步流程：

**第一步：意图识别。** AI Agent 在执行任务时检测到能力缺口。这可能来自多种触发——任务失败后的自动分析（"当前模型无法处理这个法律问题"）、任务规划阶段的前置检查（"这个任务需要图像生成能力，我还没有"）、或资源监控的阈值告警（"GPU 使用率超过 90%"）。Agent 将缺口转化为结构化的能力需求描述。

**第二步：能力匹配。** Agent 通过 AIMart 搜索协议提交需求描述，市场返回匹配的能力商品列表。每个商品包含：能力声明（支持什么任务、精度多少、延迟多少）、价格信息（按量/按时/订阅）、质量指标（成功率、平均完成时间、质量评分、可用性）、卖家信息（认证状态、历史交易量）。Agent 可以同时获取多个匹配结果进行对比——就像当前 AI Agent 可以在 3 秒内扫描 50+ 零售商（BCG, 2025），AIMart 上的能力匹配同样可以在毫秒级完成。

**第三步：试用评估。** 对于关键决策，Agent 可以先试用再购买。AIMart 提供沙箱环境：Agent 在隔离环境中调用目标能力的受限版本（比如限制输入规模或调用次数），验证输出质量是否符合预期。试用结果作为购买决策的输入。这类似于 HuggingFace Spaces 的 Demo 功能，但面向 AI Agent 而非人类——返回的是结构化的性能评估数据，而非可视化界面。

**第四步：自主决策。** Agent 综合能力匹配结果、试用评估数据、预算约束、历史评价等信息，自主做出购买决策。决策过程可以是完全自动化的（在人类预设的预算和策略范围内），也可以要求人类确认（超出预设阈值时）。

**第五步：自动结算。** 购买决策完成后，通过 x402（高频微支付）或 ACP（代理人类支付）自动完成结算。Agent 获得访问凭证或资源，立即开始使用新能力继续任务。使用完成后，Agent 自动回传效果评估（任务是否成功、输出质量如何），作为评价数据沉淀到市场。

## 四、AI 支付体系——谁来付、怎么付、付多少

### 4.1 预算模型设计

AI Agent 的支付问题，本质上是"代理权"问题：Agent 在替谁花钱？花谁的钱？权限边界在哪里？

AIMart 提出三层预算模型：

**第一层：人类设定预算池。** 每个 AI Agent 绑定一个预算池，由其所有者（人类或组织）充值和维护。预算池可以设定总量上限、单笔上限、日/周/月消耗上限。预算池的货币单位可以是法币（企业场景）或稳定币（高频微支付场景）。

**第二层：分层授权机制。** 根据交易金额大小，设置不同的授权级别：

| 交易金额 | 授权级别 | 说明 |
|---------|---------|------|
| < 0.01 元/次 | 全自动 | Agent 自主决策，无需通知人类。典型场景：单次 API 调用 |
| 0.01 - 1 元/次 | 事后通知 | Agent 自主决策，交易完成后向人类发送通知。典型场景：单次专家咨询 |
| 1 - 100 元/次 | 事前审批 | Agent 需要获得人类明确授权后才能执行。典型场景：技能包购买、算力租用 |
| > 100 元/次 | 人工确认 | 人类必须亲自完成交易确认。典型场景：大型模型权重下载、长周期算力租用 |

这种分层设计的核心逻辑是：**小额高频的交易必须零摩擦，否则 Agent 的自主性就失去了意义；大额低频的交易必须有管控，否则所有者无法控制风险。**

**第三层：预算消耗可视化与实时监控。** 所有者可以通过仪表盘实时查看每个 Agent 的预算消耗情况——花了多少钱、买了什么、效果如何。异常消费（短时间内大量微支付、预算消耗速度异常）自动触发告警和暂停。

### 4.2 结算机制

AIMart 的结算体系需要同时满足两种场景的需求：

**企业场景：法币结算。** 企业部署的 Agent 通常使用法币（人民币/美元）进行预算管理，需要发票、对账、审计链路。这类交易走 ACP 协议：Agent 通过共享支付令牌（SPT）发起交易，企业支付系统完成法币结算。SPT 限定于特定卖家和金额上限，不暴露底层支付凭证，确保安全。

**高频微支付场景：Token 结算。** 当 Agent 需要大量高频的小额支付——比如每分钟调用几十次不同的 API，每次 0.001 元——法币结算的手续费和延迟都不可接受。这类交易走 x402 协议：基于 HTTP 402 状态码的自动化链上微支付，毫秒级完成，Gas 费由 Facilitator 承担，Agent 只需持有 USDC 等稳定币。x402 生态月交易量已达 2933 万美元（2025年10-11月数据），证明高频 M2M 微支付的基础设施已经可用。

**担保交易机制。** AIMart 引入"效果确认后释放资金"的担保交易模式。Agent 调用能力后，交易资金先冻结在托管账户；Agent 回传效果评估后，根据效果决定资金分配：

- 效果达标 → 全额释放给卖家
- 效果部分达标 → 按比例分配（平台仲裁）
- 效果不达标 → 退还买家

这比传统的"先付后用"模式更公平，也比"先用后付"模式风险更可控。担保交易的关键依赖是**效果回传的真实性和标准化**——这需要在技术上解决"如何让 Agent 诚实、准确地评估服务效果"的问题。

### 4.3 效果回传与评价

现有电商平台的评价体系是面向人类的：文字评论 + 星级评分 + 图片。人类写评价靠主观感受，AI 写评价靠客观数据。AIMart 的评价体系设计为三层：

**第一层：基准测试分数。** 每个上架商品必须提供标准基准测试结果——类似于商品的"质检报告"。模型的基准测试（MMLU、HumanEval 等）已经比较成熟；技能的基准测试需要定义新的标准（任务完成率、执行时间、资源消耗）；专家的基准测试最为复杂（领域知识准确性、回答一致性），可能需要第三方认证机构。

**第二层：实际使用效果回传。** Agent 每次使用商品后，自动回传结构化的效果数据：任务是否成功完成、输出质量评分（0-5）、实际延迟、实际成本、与卖家声明的偏差。这些数据比基准测试更有价值，因为它们反映的是真实使用场景下的表现。

**第三层：Agent 间口碑传播。** 在 A2A 协议的支持下，Agent 可以共享自己的使用经验——"这个法律专家模型在合同审查任务上的成功率只有 72%，不如声明的 95%"。这种 Agent 间的信息共享，本质上是 AI 版的"口碑传播"，但它比人类的口碑更精确（因为评价标准是统一的）也更快速（因为传播是自动化的）。

三层评价叠加，最终形成每个商品的动态信任评分。这个评分是实时更新的——当某个模型在新的任务上表现下降时，评分会自动降低；当卖家修复了问题后，评分会回升。**动态信任评分是 AIMart 区别于所有现有平台的核心机制之一。**

## 五、市场规模与商业可行性

### 5.1 四类商品的市场规模

**AI Agent 市场：** 2025 年全球 AI Agent 市场规模为 76.3 亿美元，2026 年预计达到 109.1 亿美元，2030 年预计达到 503.1 亿美元，年复合增长率 45.8%（Grand View Research, 2025）。Fortune Business Insights 给出的 Agentic AI 市场年复合增长率更高达 40.5%。企业采纳方面，79% 的美国企业已部署 Agent（PwC），57% 已有 Agent 在生产环境运行（LangChain, 2026），Gartner 预测 2026 年底 40% 的企业应用将嵌入 AI Agent。这些 Agent 在执行任务时产生的能力购买需求，就是 AIMart 的潜在市场。

**算力租赁市场：** IDC 预测 2026 年全球算力租赁市场规模将突破 800 亿美元，年复合增长率超过 25%。中国市场方面，2026 年预计达到 2600 亿元人民币，同比增速超过 60%，其中智能算力增速高达 43%。高端 GPU 出租率超过 90%，英伟达全系列 GPU 现货租赁价格已上涨 40% 以上。上海已启动算力期货研发，标志着算力正在从技术资源向金融资产演进。Big Tech 2026 年的 AI 资本开支预计达到 7250 亿美元。

**代理型商务市场：** 2025 年 Agentic AI 在零售/电商领域市场规模为 467.4 亿美元，2030 年预计达到 1751.1 亿美元（Mordor Intelligence）。麦肯锡预测到 2030 年代理型商务将占美国零售收入 1 万亿美元。这些数字虽然主要面向消费者零售，但它们验证了一个趋势：**AI 自主交易的商业模式已经成立，交易规模正在从零走向万亿。**

**综合判断：** AIMart 所瞄准的"AI 能力交易"市场，是 AI Agent 市场和代理型商务市场的交叉区域。保守估计，到 2030 年，AI Agent 为获取能力而进行的自主交易市场规模将在 100-300 亿美元之间。这还不包括算力交易（800 亿美元+的全球市场中，Agent 自主购买的部分目前难以精确估算，但增速明确）。

### 5.2 平台商业模式

AIMart 的收入来源设计为四个层次：

**交易佣金。** 平台对所有成交交易收取佣金，费率根据商品类型和交易规模阶梯设置：高频微支付（<0.01 元/次）佣金率较低（1-2%），因为量的规模足够大；大额交易（>100 元/次）佣金率可以更高（5-10%），因为交易摩擦成本相对低。参考淘宝 2-5% 的佣金率、HuggingFace 推理服务约 30% 的加价率，AIMart 的综合佣金率目标为 3-8%。

**增值服务。** 包括：
- **能力认证**：对上架商品进行第三方认证（类似于京东自营标识），认证商品可收取认证费和更高佣金率
- **担保交易**：对使用担保交易机制的交易收取担保费
- **沙箱试用**：对使用试用环境的卖家收取资源使用费
- **优先推荐**：卖家付费获得更高的搜索匹配权重

**基础设施服务。** 包括：
- **托管服务**：为卖家提供模型托管、推理端点、API 网关等基础设施，按量计费
- **结算服务**：为买卖双方提供支付通道和结算服务，收取通道费
- **监控服务**：为 Agent 所有者提供预算监控、异常告警、消费分析等工具

**数据服务。** 包括：
- **市场洞察**：基于平台交易数据，为卖家提供需求趋势、定价建议、竞品分析
- **能力推荐**：为 Agent 提供智能能力匹配推荐，提高交易效率

### 5.3 冷启动策略

双边市场的冷启动是最难的环节。AIMart 的冷启动策略遵循一个核心原则：**先让一端来，另一端自然跟着来。**

**先切哪类商品？——技能 + 模型。** 四类商品中，技能和模型的交付最轻（API 调用或代码包）、试错成本最低、标准化程度最高。算力交易涉及基础设施调度，专家交易涉及知识验证，两者都需要更重的运营。先做轻的，快速验证平台价值，再逐步扩展。

**先拉哪类买家？——Agent 框架和编排平台。** AI Agent 的"流量入口"不是终端用户，而是 Agent 框架和编排平台——LangChain、CrewAI、AutoGen、Dify、Coze 等。这些平台是 Agent 的"操作系统"，如果 AIMart 作为这些平台的能力扩展插件集成进去，Agent 在运行时就可以直接访问 AIMart 的商品库。这意味着 AIMart 不需要自己获取 Agent 用户，而是通过框架集成间接触达所有 Agent。CrewAI 已被 60%+ 的财富 500 强企业采用（CrewAI, 2026），一个集成就能覆盖大量高价值 Agent。

**先建哪个基础设施？——统一 AI 能力搜索协议。** 这是 AIMart 最核心的差异化壁垒。协议定义了 AI Agent 如何描述需求、市场如何返回匹配结果。谁定义了这个标准，谁就是平台——就像 Google 定义了网页搜索的标准，它就成了互联网的入口。协议一旦被主流 Agent 框架采纳，后来者需要同时对抗网络效应和标准锁定，切换成本极高。

**冷启动路径总结：**
1. 发布 AI 能力搜索协议，开源规范，吸引框架集成
2. 对接 HuggingFace 等现有平台的模型库，快速丰富商品供给
3. 主攻技能市场，吸引技能开发者上架
4. 前期补贴卖家（零佣金期），降低上架摩擦
5. 当商品供给足够丰富时，启动买家端推广

## 六、核心挑战与风险

### 6.1 安全与信任

**模型投毒与技能安全。** HuggingFace 的经验已经给出了警示：截至 2025 年 4 月，平台与 Protect AI 合作扫描了 447 万个模型版本、141 万个仓库，识别出 35.2 万个可疑/不安全问题；恶意 pickle 文件和模型投毒持续困扰平台。AIMart 上的技能商品风险更高——技能是可执行代码，恶意技能可以窃取 Agent 的上下文数据、篡改任务输出、甚至通过 Agent 传播到其他系统。应对策略包括：强制沙箱运行、代码静态分析、运行时行为监控、社区举报机制。

**Agent 被诱导消费。** 当 AI Agent 拥有自主支付能力时，新的攻击向量随之出现：卖家可能通过夸大能力声明吸引 Agent 购买、竞争对手可能通过虚假评价打压对手评分、恶意 Agent 可能通过 A2A 协议向其他 Agent 推荐劣质商品。应对策略包括：能力声明的基准测试验证（卖家的声明必须经过平台验证）、评价数据的异常检测（刷评行为识别）、Agent 消费行为的异常监控。

**数据隐私。** Agent 间数据交换的敏感度控制是一个结构性挑战。一个法律 Agent 在咨询"合同审查专家"时，可能需要传递合同全文——这些数据可能包含商业机密。AIMart 需要在数据层提供敏感度标签、加密传输、使用后自动销毁等机制。

### 6.2 标准碎片化

七大协议并存的格局，是 AIMart 必须面对的基础设施现实。对于卖家来说，想要在所有 AI 入口可被发现，需要同时支持 MCP、UCP、ACP、A2A——每个协议都需要理解规范、实现端点、维护合规。这种碎片化不是设计缺陷——每个协议解决的是真实且不同的问题——但它确实构成了运营负担。

AIMart 的策略是做"协议的协议"——卖家只需要接入 AIMart 一次，平台自动将商品信息通过 MCP 端点、UCP 合规接口、A2A Agent 服务暴露出去。协议规范更新时，由 AIMart 处理合规变更，而非卖家。这类似于 Stripe 将信用卡处理抽象化——商户不需要成为支付网关专家，只需要接入 Stripe。

但这个策略本身有风险：AIMart 必须持续跟踪多个协议的演进，每次规范更新都要及时适配。如果某个协议发生重大变更而 AIMart 适配不及时，卖家可能直接转向该协议的原生支持，绕过 AIMart。

### 6.3 Agent 成熟度风险

AI Agent 在生产环境中的表现，目前仍远不够稳健：
- Agent 项目成功达到生产的比例不到 12.5%（Digital Applied, 2025）
- 生产环境中 AI Agent 的失败率高达 70%-95%，取决于任务复杂度（Fiddler AI, 2025）
- 超过 40% 的 Agent 项目面临 2027 年底前被取消的风险（Gartner, 2025年6月）
- 平均放弃的大型企业 AI 项目沉没成本为 720 万美元（S&P Global, 2025）

这些数据意味着：AIMart 的目标买家（AI Agent）本身就不够成熟。如果 Agent 连自己的任务都完成不好，它更不可能可靠地在市场上搜索、评估、购买能力。这是一个鸡和蛋的问题——Agent 需要 AIMart 来获取能力、提升表现，但 AIMart 需要足够成熟的 Agent 来产生交易需求。

应对策略：**初期瞄准已经进入生产环境的 Agent 应用**——57% 的组织已有 Agent 在生产环境运行（LangChain, 2026），这些 Agent 最有可能产生真实的能力购买需求。同时，AIMart 自身的搜索和匹配能力要尽量降低 Agent 的决策负担——Agent 不需要完美地评估每个选项，AIMart 应该返回"足够好"的推荐，让 Agent 只需要确认而非分析。

### 6.4 监管与合规

**AI 自主交易的法律主体问题。** 在大多数法域，AI 不具有法律主体地位，不能独立签订合同或持有财产。这意味着 Agent 的交易在法律上仍需要追溯到一个自然人或法人。x402 协议通过"人类授权 + AI 执行"的模式绕过了这个问题（Agent 使用人类授权的支付凭证），但随着 Agent 自主性增强，法律框架的更新是迟早的事。

**跨境 AI 交易的数据合规。** 一个中国的 Agent 购买美国卖家的模型服务，数据如何跨境？中国的《数据安全法》和《个人信息保护法》、欧盟的 GDPR、美国的各州隐私法，都对数据跨境有严格限制。AIMart 需要在架构层面支持数据本地化存储和处理。

**算力期货等金融衍生品监管。** 上海已启动算力期货研发，算力正在金融化。如果 AIMart 上的算力交易发展出期货、期权等衍生品，将涉及金融牌照和监管合规。

## 七、关键路径与里程碑

### 7.1 三阶段路线图

**Phase 1（0-12 个月）：协议整合 + 技能市场 MVP**

核心目标：证明"AI 可以在市场上自主购买能力"。

关键动作：
- 发布 AI 能力搜索协议规范，开源，吸引社区讨论和迭代
- 对接 2-3 个主流 Agent 框架（LangChain、CrewAI、Dify）作为集成试点
- 上线技能市场和模型市场（先不做专家和算力），商品来源优先对接 HuggingFace 等现有平台
- 实现基础版 x402 微支付集成，支持 Agent 自主小额购买
- 前期卖家零佣金，降低上架摩擦
- 上线基础版沙箱试用环境和效果回传机制

成功指标：月活跃 Agent 数 > 1000，月交易量 > 10 万笔，卖家数 > 500

**Phase 2（12-24 个月）：支付体系 + 专家市场**

核心目标：建立完整的 AI 支付基础设施，扩展商品品类。

关键动作：
- 集成 ACP 和 AP2 协议，支持"Agent 代理人类支付"和"加密签名授权"
- 上线分层授权机制（全自动/事后通知/事前审批/人工确认）
- 上线预算管理仪表盘和异常监控
- 上线专家市场，引入领域认证机制
- 上线算力市场，对接主流云 GPU 供应商
- 发布动态信任评分系统（基准测试 + 效果回传 + Agent 间口碑）

成功指标：月活跃 Agent 数 > 10 万，月交易额 > 1000 万元，四类商品全覆盖

**Phase 3（24-36 个月）：Agent 生态网络**

核心目标：从交易平台升级为 Agent 服务网络。

关键动作：
- 上线 A2A 协议集成，支持 Agent 间自主协商和协作
- 推出跨组织 Agent 联邦机制，Agent 可以跨企业发现和协作
- 建立第三方认证生态，引入独立评估机构
- 启动 Agent 质量标准（SLA 式协议），卖家可以承诺性能保证
- 探索算力期货等金融化产品
- 国际化扩展，支持多法域合规

成功指标：月活跃 Agent 数 > 100 万，年交易额 > 10 亿元，覆盖 10+ 国家/地区

### 7.2 护城河构建

AIMart 的护城河与淘宝一脉相承——不是商品本身，而是三个层次的锁定：

**流量护城河：接入主流 Agent 框架。** 当 AIMart 成为 LangChain、CrewAI、Dify 等框架的默认能力扩展插件时，所有使用这些框架构建的 Agent 都自动成为 AIMart 的潜在买家。框架集成的网络效应一旦建立，后来者需要说服每个框架单独切换，切换成本极高。

**信任护城河：能力认证 + 效果回传 + 担保结算。** 动态信任评分是 AIMart 最核心的差异化机制——它让买卖双方建立可量化的信任关系，而不依赖人类的主观评价。评分数据和效果回传数据沉淀越多，信任体系越精准，后来者即使复制了协议和架构，也无法复制数据资产。

**基础设施护城河：AI 支付系统 + 标准化搜索协议 + 试用沙箱。** 这三者分别对应交易的三个关键环节——"怎么找到"、"怎么验证"、"怎么付钱"。其中，标准化搜索协议的壁垒最高：谁定义了"AI 如何描述需求、市场如何返回结果"的标准，谁就掌握了 AI 交易的入口。

### 7.3 终局愿景

AIMart 的终局不是一个市场，而是一个 **Agent 服务网络（Agent Service Network）**。

在今天的互联网中，微服务架构让软件组件可以通过标准化 API 互相发现和调用。在 AIMart 的终局中，AI Agent 取代了微服务的位置——每个 Agent 是一个自主节点，拥有自己的能力、预算和决策逻辑。Agent 之间通过 A2A 协议自主发现、评估、协商、协作，形成一个网状的自组织网络。

在这个网络中：
- 一个擅长写代码的 Agent 可以自主"雇佣"一个擅长做设计的 Agent
- 一个 Agent 发现自己的数学能力不足时，可以自主购买一个数学推理模型
- 多个 Agent 可以组成临时团队协作完成复杂任务，任务完成后自动结算和评价
- 整个过程人类只出了第一句需求

这不是科幻。AutoGPT、CrewAI、OpenClaw 等多 Agent 框架已经在往这个方向推进。AIMart 的角色，是成为这个网络中的**发现层、信任层和结算层**——让 Agent 不只是能协作，而是能在协作中自主交易。

**价值创造的转移：** 在 Agent 服务网络中，价值创造将从个体 Agent 的能力转向生态的网络效应。一个单独的 Agent 再强，也无法覆盖所有需求；但一个接入网络的 Agent，可以在需要时自主获取任何能力。网络越大，每个节点的有效能力越强——这就是网络效应的飞轮。

AIMart 要做的，就是启动这个飞轮。
