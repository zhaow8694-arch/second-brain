## 六、 帝国三大基石 (The Three Pillars)

*帝国要实现真正的"自进化"，必须打下三大基石。这是所有上层建筑的基础。*

### 6.1 🧱 基石一：统一日志与元数据系统 (The Unified Log)

**目的:** 进化需要原材料。如果每个部门的日志格式都不一样，教导团就没法分析。

**设计原则:**
- 所有 Agent 的决策过程（Thought Process）必须被标准化记录
- 日志包含：时间戳、会话ID、Agent角色、任务目标、决策内容、成本消耗、结果状态
- 日志格式统一为结构化 Markdown，便于教导团扫描和 AI 分析

**对应代码:** `core/battle_log.py` — 基础日志；`core/log_decorator.py` — 标准化日志装饰器

### 6.2 🧱 基石二：动态指令加载器 (Dynamic Prompt Loader)

**目的:** 实现"不重启程序就能换脑子"。

**设计原则:**
- Agent 的性格（role/goal/backstory）不写死在代码里
- 所有 Prompt 从 `config/prompts/` 文件夹读取
- 教导团修改了 Prompt 文件，Agent 下一秒就进化
- 支持热加载：每次执行任务时重新读取最新 Prompt

**对应代码:** `config/prompts/` — Prompt 文件目录；`core/prompt_loader.py` — 动态加载器

### 6.3 🧱 基石三：质量门禁与多模型交叉审计 (Quality Gates)

**目的:** 只有通过审计的进化才是正向进化。

**设计原则:**
- 引入多模型交叉审计：同一个产出由两个独立审查员分别审查
- 只有双审查都通过的产出才能放行
- 宪兵局具备识别"有害进化"的能力（如 Agent 尝试绕过风控）
- 审计结果记录到日志，供教导团复盘

**对应代码:** `core/quality_gate.py` — 质量门禁系统

## 七、 战略强化补丁 V2.1 (Strategic Enhancement Patches)

*本章节记录从 V2.0 到 V2.1 的战略强化内容，解决从"模拟脚本"向"实盘主权智能体"跨越中的核心短板。*

### 7.1 补丁一：状态持久化与断点恢复 (State Persistence)

**解决的问题:** 程序中断后所有进度丢失，重新运行需重复支付 API 费用。

**实现方案:**
- **检查点机制:** 每个任务完成后强制执行"状态落盘"，将当前上下文、已获取变量、Agent 心路历程存入日志
- **热启动能力:** 系统启动时优先扫描 `battle_logs/`，若存在未完成任务，直接从断点处唤醒
- **效果:** 节省 40%-60% 的重复计算成本

**对应代码:** `core/battle_log.py` — 作战日志系统（已实现检查点落盘）

### 7.2 补丁二：混合推理引擎 (Hybrid Inference)

**解决的问题:** 所有任务（包括简单的网页摘要）都调用昂贵模型，导致算力预算迅速耗尽。

**实现方案:**
- **动态路由:** 根据任务复杂度自动分配模型层级
  - **low（搜集/翻译）:** DeepSeek-Chat，成本极低
  - **medium（量化/策略）:** DeepSeek-Reasoner，平衡速度与深度
  - **high（审计/决策）:** DeepSeek-Reasoner，最高推理质量
- **效果:** 在不降低最终决策质量的前提下，整体运营费用降低 75% 以上

**对应代码:** `core/model_router.py` — 三层模型路由（已实现）

### 7.3 补丁三：自我进化反馈环 (The Feedback Loop)

**解决的问题:** 被宪兵驳回的错误，Agent 无法形成长期教训，下次大概率会犯同样的错。

**实现方案:**
- **驳回分析协议:** 宪兵局长执行"否决"时，强制输出结构化驳回原因
- **教导团学习任务:** 定期读取驳回记录，自动更新 `config/prompts/` 下的 Agent 指令
- **进化指标:** 同一类型的错误在 48 小时内不得出现第二次

**对应代码:** `core/quality_gate.py` — 质量门禁（驳回记录）；`core/academy.py` — 教导团复盘；`core/prompt_loader.py` — 动态指令加载（热更新）

### 7.4 补丁四：财务主权网关 (Financial Gateway) — 规划中

**解决的问题:** Agent 无法自主支付 API 费用或执行实盘下单。

**规划方案:**
- 引入智能合约钱包（如 Safe），为每个军团配置独立钱包
- 分权治理：总司令拥有最高权限，Agent 仅拥有受限签名权
- 单笔交易限额、每日总额限额、仅限支付给指定供应商

**状态:** 📋 规划中，待技术条件成熟后实施

## 八、 铁血纪律与审计细则 (Operational Discipline)

### 8.1 三大铁律

1. **严禁越级:** 野战军团禁止直接向总司令提交报告，必须先通过宪兵局长签字
2. **数据主权:** 所有 Agent 生成的日志、代码、策略必须存储于 `battle_logs/` 和 `core/` 目录，禁止离线存储
3. **成本熔断:** 后勤部一旦监测到当日 API 消耗超过设定的 $5.00（或自定义额度），所有非核心任务必须立即挂起

### 8.2 一票否决细则

- **金融交易:** 单笔回撤 > 2% 必须否决
- **代码安全:** 存在 API 密钥泄露、SQL 注入、XSS 等漏洞必须打回
- **合规审查:** 宣发文案违反平台政策必须重写

### 8.3 进化红线 [新增]

- **影子测试:** 教导团修改 Agent Prompt 前，必须在沙箱环境中运行"影子测试"，验证新指令不会导致逻辑退化或产生有害行为
- **测试通过标准:** 新指令在历史失败案例上的通过率 ≥ 80%，且不引入新的失败模式
- **对应代码:** `core/academy.py` → `shadow_test()` 函数

## 九、 合规与法律风险 (Compliance & Legal Risk) [新增]

*本章节为 V2.4 根据 Grok 外部评审建议新增。帝国在追求高速增长的同时，必须正视法律与合规红线。*

### 9.1 交易合规 (Trading Compliance)

| 风险项 | 当前状态 | 防护措施 |
|--------|----------|----------|
| 自动化 EA 交易监管 | 🟢 代码仅生成策略分析，不涉及实盘自动下单 | `quality_gate.py` 止损红线检查 |
| 跨境金融合规 | 🟢 无实盘交易执行逻辑 | 未来接入合约钱包时需单独审计 |
| 策略知识产权 | 🟡 策略代码存储在本地，未加密 | 建议：`security_auditor.py` 增加加密扫描 |

**红线规则:**
- 所有交易策略必须经过宪兵队止损审计（止损 > 2% 否决）
- 禁止使用"保证收益""稳赚"等违规表述
- 实盘接入前必须通过外部合规审计

### 9.2 广告与平台合规 (AdTech Compliance)

| 风险项 | 当前状态 | 防护措施 |
|--------|----------|----------|
| 批量生成带广告小程序 | 🟢 代码生成 HTML 文件，未自动发布到应用商店 | 无自动发布逻辑 |
| 全球矩阵发帖 | 🟢 `content_factory.py` 仅生成文案文件，未接入真实 API 发帖 | 文案经过 `quality_gate.py` 合规检查 |
| 平台反作弊规则 | 🟢 影子特工处提供身份轮换，但未实际使用 | `identity_manager.py` 已就绪 |

**红线规则:**
- 所有推广文案必须经过合规预审（`quality_gate.py` 的 `marketing_copy` 规则）
- 禁止使用绝对化用语（"最好""第一""唯一"）
- 禁止金融收益承诺（"保证盈利""稳赚"）
- 当前系统仅生成内容，不自动发布到任何第三方平台

### 9.3 数据合规 (Data Compliance)

| 风险项 | 当前状态 | 防护措施 |
|--------|----------|----------|
| API 密钥管理 | 🟢 密钥存储在 `.env` 文件，不提交到版本控制 | `security_auditor.py` 定期扫描 |
| 用户数据处理 | 🟢 当前系统不收集任何用户个人信息 | 无用户数据存储 |
| 日志数据安全 | 🟡 日志存储在本地文件系统，未加密 | 建议：增加日志加密选项 |

**红线规则:**
- 严禁将 API 密钥硬编码到代码中
- 所有日志存储在本地 `battle_logs/` 目录，禁止外传
- 未来涉及用户数据时，必须遵守 GDPR/CCPA 等隐私法规

### 9.4 合规审计官角色

在宪兵队中增设 **"法律合规审计官"** 角色，职责：
1. 审查所有对外发布内容（文案、产品描述）的合规性
2. 监控各平台政策更新，及时调整合规规则
3. 定期生成合规审计报告，提交统帅部

**对应代码:** `core/quality_gate.py` — 已内置 `marketing_copy` 合规规则
