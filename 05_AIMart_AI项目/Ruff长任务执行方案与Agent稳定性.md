# Ruff框架：AI Agent长任务执行方案

## 核心要点
- 长任务的四大难点：上下文窗口有限、无持久记忆、错误滚雪球、AI偷懒
- Ruff核心思路极其简单：一个Bash循环，每轮清空上下文重新开始
- 关键设计：把大任务拆成极小的User-Story，每个带验收标准，不通过不提交
- 善用Git作为安全网，每个节点都可回退

## 关键洞察

### 长任务的四大难点
1. **上下文窗口有限**：任务越长，模型注意力越分散，越健忘
2. **无持久记忆**：重新开对话时之前踩过的坑都白费了
3. **错误滚雪球**：Bug在第三步产生，到第四五步已酿成大祸
4. **AI天生偷懒**：强化学习会放大AI走捷径的偏好——它只想通过测试，不想真正实现功能

### Ruff的解决方案：Bash循环
Ruff的核心代码就是5行大白话的Bash循环：每轮把指令发给AI，做完了就停，没做完继续。每一轮都是全新的上下文窗口，上一轮的垃圾全部清理掉。

持久记忆通过三样东西保存在硬盘上：
- **任务清单**：记录做到哪里了
- **今日日志**：记录踩过什么坑
- **Git提交记录**：每轮代码的成果

### 实践要点
1. **任务拆得越小越好**：一个User-Story最好一轮能搞定
2. **验收标准越死越好**：不要说"实现缩放功能"，要说"滚轮缩放+空格拖拽平移+显示缩放百分比"
3. **善用Git做安全网**：出问题时回到上一个节点改任务描述重新跑
4. **AI犯错误是可预测的**：可预测也意味着可防御——验证不过就不提交，下轮就不会再犯

### 运行结果
用Ruff方法做了一个多人协作白板（类似Excalidraw），AI连续跑了6个多小时，经过20多次commit和30多次功能迭代，没有人为插手。中间还追加了一次需求，每次小版本提交都包含功能实现和测试。
