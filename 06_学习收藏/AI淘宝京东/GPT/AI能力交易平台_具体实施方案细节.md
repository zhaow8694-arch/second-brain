# 1. 实施总纲

## 1.1 项目定位

本项目不是单一 AI 产品，也不是 AI 工具导航站，而是一个 **AI 能力流通与交易平台**。

平台的核心任务是：

```text
让模型、Agent、API、Prompt/Workflow、专家服务、方案包、算力、数据处理、部署服务、评测服务等 AI 能力，
可以被标准化上架、被客户搜索、被商家销售、被平台担保交易、被项目化交付、被评价和复购，
并最终可以被 AI Agent 自动读取、比较、购买、组合和调用。
```

平台早期应该形成一个最小交易闭环：

```text
商家开店
→ 上架能力商品
→ 商家带客户 / 平台获客 / 渠道导入客户
→ 客户搜索商品或发布需求
→ 平台辅助诊断和匹配
→ 商家报价
→ 平台担保交易
→ 商家交付
→ 客户验收评价
→ 平台沉淀交易数据、交付数据、效果数据
→ AI Agent 逐步读取和调用能力
```

## 1.2 核心实施原则

### 原则一：战略开放

平台不限定：

```text
不限定客户：企业、个人、团队、AI 使用者、Agent 开发者、工厂、电商、教育、咨询公司等都可以。
不限定行业：制造、电商、内容、客服、教育、法律、办公、数据分析等都可以。
不限定能力类型：模型、Agent、API、专家、算力、方案包、工作流、部署服务等都可以。
不限定流量来源：平台自有流量、商家自带客户、渠道导流、Agent 调用都可以。
```

### 原则二：规则硬化

平台必须统一：

```text
能力商品如何上架
能力卡片如何填写
报价如何生成
订单如何履约
验收如何确认
评价如何沉淀
商家如何认证
争议如何处理
AI Agent 如何读取
风险如何分级
数据如何保护
```

### 原则三：先闭环，后规模

早期不要追求“能力很多、行业很多、商家很多”，而是先验证：

```text
商家是否愿意入驻
商家是否愿意带客户到平台成交
客户是否愿意在平台下单
平台是否能促成交易
交易是否能按里程碑交付
评价是否能沉淀
能力卡片是否能被 AI 读取
```

### 原则四：商家带流量，平台沉淀交易

早期平台没有强流量时，应把商家作为重要冷启动入口。

平台要给商家的价值不是简单“给你曝光”，而是：

```text
帮你开店
帮你包装 AI 能力
帮你生成商品页
帮你管理客户需求
帮你报价
帮你担保交易
帮你做交付里程碑
帮你沉淀评价和案例
帮你管理续费
帮你未来接入 AI Agent 自动采购
```

### 原则五：人类界面 + AI Agent 接口并行设计

早期用户主要仍是人类，但底层要从第一天支持 AI 可读。

```text
人类看到商品页、店铺页、需求页、订单页。
AI Agent 读取能力卡片、接口文档、价格、权限、评分、风险等级、调用方式。
```

# 2. 平台阶段目标

## 2.1 第一阶段：商家开店 + 人工撮合交易

周期：0-90 天  
目标：跑通最小交易闭环。

核心结果：

```text
20-50 个高质量商家
50-100 个能力商品
10-30 条真实客户需求
5-20 个真实订单或试点
1 套能力卡片 v0.1
1 套交易与履约流程
1 套基础评价机制
1 套商家后台和平台后台
```

此阶段 AI Agent 只需要做到：

```text
可读取能力卡片
可搜索能力
可比较基础字段
可生成推荐说明
暂不开放自动大额下单
```

## 2.2 第二阶段：标准化交易 + 评价沉淀

周期：90-180 天  
目标：从人工撮合变成半自动交易平台。

核心结果：

```text
商家可自助上架能力
买家可自助发布需求
平台可自动推荐商品/商家
订单可按里程碑管理
客户评价和交付数据进入评分体系
API 类能力可按次调用或订阅
商家有数据看板
平台有交易风控和仲裁机制
```

## 2.3 第三阶段：AI Agent 采购助手

周期：180-365 天  
目标：让 AI Agent 能在平台内辅助完成采购决策。

核心结果：

```text
Agent 可通过 API/MCP 搜索能力
Agent 可读取完整能力卡片
Agent 可生成能力组合方案
Agent 可发起报价请求
Agent 可在预算内试用低风险能力
高风险动作需要人类确认
```

## 2.4 第四阶段：AI 能力交易网络

周期：365 天以后  
目标：成为 AI Agent 与外部能力之间的交易与调用基础设施。

核心结果：

```text
第三方 Agent 可接入平台
企业可配置 Agent 采购权限
商家可开放 API/MCP 能力
平台支持组合工作流交易
平台支持能力路由与自动结算
平台形成跨行业能力图谱和真实执行评分体系
```

# 3. MVP 总体范围

## 3.1 MVP 必须实现的功能

第一版 MVP 不要过大，但必须覆盖完整闭环。

### 买家侧

```text
注册/登录
浏览能力商品
浏览商家店铺
搜索能力
发布需求
填写需求诊断表
查看推荐方案
查看报价
下单/支付/担保交易
查看订单进度
提交验收
提交评价
```

### 商家侧

```text
注册/入驻申请
商家认证资料提交
开店
上架能力商品
填写能力卡片
设置价格/报价方式
接收客户需求
提交报价
管理订单
提交交付物
维护里程碑
查看评价
查看经营数据
```

### 平台侧

```text
商家审核
商品审核
类目管理
需求审核
撮合推荐
订单监管
资金/结算管理
评价审核
纠纷处理
能力评分管理
风险标签管理
平台数据看板
```

### AI 原生能力

```text
能力卡片 JSON
能力搜索 API
能力详情 API
能力比较接口雏形
报价请求接口雏形
反馈提交接口雏形
```

## 3.2 MVP 暂时不做的功能

```text
不做完全自动付款
不做开放式所有商家无审核入驻
不做复杂广告竞价系统
不做完整算力实时交易市场
不做大型模型托管系统
不做全自动多 Agent 编排
不做复杂国际化
不做移动端 App
不做高风险行业自动化决策
```

## 3.3 MVP 核心验证问题

```text
1. 商家愿不愿意按平台标准上架能力？
2. 商家愿不愿意把自己的客户带到平台成交？
3. 买家是否愿意在平台发布 AI 需求？
4. 平台是否能把模糊需求变成可报价需求？
5. 商家是否能在平台完成交付？
6. 平台担保交易是否能提升信任？
7. 能力卡片是否能承载不同类型 AI 能力？
8. AI 搜索能力是否能返回可用结果？
```

# 5. 能力商品体系实施细节

## 5.1 商品类型

平台早期支持以下商品类型：

| 类型 | 说明 | 交易方式 |
|---|---|---|
| Agent / 技能 | 可执行特定任务的 AI Agent 或工具 | 按次、订阅、报价 |
| API 能力 | OCR、翻译、摘要、图像处理等 API | 按次、套餐、订阅 |
| 专家服务 | 咨询、部署、顾问、审计、培训 | 项目制、小时制、报价 |
| 方案包 | 面向某类业务问题的整体方案 | 项目制、试点包、订阅 |
| 模型能力 | 模型 API、模型部署、微调服务 | 调用费、授权费、项目制 |
| Prompt / Workflow | 工作流模板、自动化流程 | 一次性购买、订阅 |
| 算力 / 部署服务 | GPU、私有部署、推理服务 | 按量、包月、报价 |
| 数据处理服务 | 清洗、标注、文档解析、知识库处理 | 按量、项目制 |
| 评测 / 安全服务 | 模型评测、Agent 测试、安全审计 | 项目制、订阅 |

## 5.3 商品上架流程

```text
1. 商家选择商品类型
2. 填写基础信息
3. 填写能力卡片
4. 上传案例/资质/示例
5. 设置价格或报价方式
6. 设置交付方式
7. 设置数据政策和风险说明
8. 提交平台审核
9. 平台审核通过后上架
10. 上架后进入搜索和推荐系统
```

## 5.4 商品审核规则

审核维度：

```text
描述是否清晰
是否夸大效果
价格是否明确
交付范围是否明确
验收标准是否明确
数据政策是否明确
风险等级是否正确
案例是否真实
是否符合平台禁售规则
```

审核结果：

```text
通过
退回修改
限制上架
禁止上架
需要补充资质
需要人工复核
```

```text
7. 平台初审
8. 补充资料
```

## 6.2 商家类型

```text

模型/API 提供商
系统集成商

```

## 6.3 商家等级

建议初期设置四级：

| 等级 | 名称 | 说明 |
|---|---|---|
| S0 | 待认证商家 | 可提交资料，但商品不上架 |
| S1 | 基础认证商家 | 通过主体认证，可上架低风险商品 |
| S2 | 平台认证商家 | 有案例、有交付能力，可参与平台推荐 |
| S3 | 优选商家 | 有稳定成交和高评分，可参与重点项目 |
| S4 | 战略商家 | 深度合作，支持 API/MCP 能力开放 |


## 6.6 商家留在平台交易的理由

# 7. 买家需求系统实施细节

## 7.1 买家入口

## 8.2 标准订单流程

```text
1. 买家提交需求或选择商品

3. 商家提交报价
4. 买家确认报价

6. 买家付款至平台担保账户
7. 商家开始交付

10. 平台按比例结算商家
11. 最终交付

13. 平台结算尾款
14. 买家评价
15. 平台更新评分
```

## 8.3 里程碑模板

### 专家服务模板

```text
阶段 1：需求确认，付款 20%
阶段 2：方案设计，付款 30%
阶段 3：实施/交付，付款 30%
阶段 4：验收/售后，付款 20%
```

### 方案包模板

```text
阶段 1：资料收集与需求确认
阶段 2：方案配置/开发
阶段 3：测试与修正
阶段 4：上线交付
阶段 5：售后维护
```

### API 商品模板

```text
充值/订阅
调用
计量
失败处理
账单生成
```

## 8.4 退款与争议规则

平台需要定义：

```text
未开始服务：可全额退款
已完成部分里程碑：按已验收阶段结算
商家延迟交付：可部分退款或赔付
买家资料不足导致延迟：不视为商家违约
输出质量争议：依据验收标准和平台仲裁
API 调用失败：自动补偿或退款
```

## 8.5 平台抽佣规则建议

初期可以设置：

```text
专家服务 / 项目制：10%-20%
标准化商品 / API：5%-15%
商家自带客户成交：低佣金，例如 3%-8%
平台撮合客户成交：高佣金，例如 10%-20%
认证商家会员：可抵扣部分佣金
```

原则：

```text
商家自带客户要低佣金，否则容易绕开平台。
平台提供撮合和担保的订单，可以收更高佣金。
```

# 10. AI Agent 接口系统实施细节

## 10.1 第一版目标

第一版不做全自动交易，但必须让 AI 能读、能搜、能比。

### 第一版 Agent 能力

```text
读取能力卡片
搜索能力
查看商品详情
比较基础字段
生成推荐方案
发起报价请求
提交反馈
```

### 第一版 Agent 不能做

```text
不能自动大额付款
不能自动上传敏感数据
不能自动签署合同
不能调用高风险能力
不能绕过人类审批
```

## 10.2 API v0.1

```http
GET /api/v1/capabilities/search?q=企业知识库&category=agent&risk_level=low
```

返回字段：

```json
  "capabilities": [
    {
      "capability_id": "cap_001",

    }
  ]
}
```

```http
GET /api/v1/capabilities/{capability_id}
```

返回完整能力卡片。


## 10.4 Agent 权限等级

| 等级 | 权限 | 是否需要人类确认 |
|---|---|---|
| L0 | 搜索和读取公开能力 | 否 |
| L1 | 比较能力和生成推荐 | 否 |
| L2 | 发起报价请求 | 可选 |
| L3 | 发起订单草案 | 是 |
| L4 | 在预算内调用低风险 API | 需要企业授权 |
| L5 | 高风险能力调用或付款 | 必须人工确认 |

```text

可访问类目

```

# 12. 风险治理与安全权限实施细节

## 12.1 风险分级

### 低风险


```text
客服 Agent

合同辅助审查
```

```text
需要数据政策说明
需要人工授权
需要日志留存
需要验收标准
```

```text
法律结论
医疗建议
金融投资建议
招聘筛选
风控决策
涉及大量个人敏感信息
```

```text
必须人工审批
必须免责声明
必须专家复核
早期不允许全自动调用
```

```text
违法用途
诈骗
攻击工具
隐私窃取
恶意爬取
侵犯版权
绕过安全系统
违法数据交易
```

```text
禁止上架
禁止交易
发现后冻结账户
```

# 22. 风险清单与应对方案

## 22.1 商家绕开平台

风险：

```text
商家把客户导到微信私下成交
```

应对：

```text
商家自带客户低佣金
平台提供担保交易
平台提供交付工具
平台沉淀评价和认证
平台提供后续复购和续费管理
```

## 22.2 商品质量参差不齐

风险：

```text
能力夸大宣传，交付不稳定
```

应对：

```text
商品审核
平台认证
真实案例要求
评价体系
退款/纠纷记录
商家等级管理
```

## 22.3 交易非标导致纠纷

风险：

```text
买家说效果不好，商家说需求变了
```

应对：

```text
需求说明书
报价确认
里程碑
验收标准
平台仲裁
阶段付款
```

## 22.4 平台冷启动困难

风险：

```text
没有买家，商家不来；没有商家，买家不来
```

应对：

```text
商家带流量
渠道合作
免费需求诊断
精选商家
人工撮合
先跑真实订单
```

## 22.5 AI 自动化过早

风险：

```text
过早开放 AI 自动付款或调用，带来安全和责任问题
```

应对：

```text
分阶段开放
权限等级
预算上限
人工审批
高风险能力禁止自动执行
```

## 22.6 数据安全风险

风险：

```text
企业资料泄露或被商家滥用
```

应对：

```text
数据政策声明
平台代理调用
权限控制
日志审计
私有化选项
数据删除机制
```

# 24. 最终执行原则

这个项目要避免陷入“只想不做”，所有讨论都要落到执行对象上。

每个新想法都必须回答：

```text
它对应哪个角色？
它解决哪个问题？
它进入哪个流程？
它需要哪个页面？
它产生什么数据？
它是否促进交易？
它是否提升信任？
它是否能被 AI Agent 读取或调用？
它是否能在 30-90 天内验证？
```

如果回答不了，就暂时不做。

最终落地路径是：

```text
先做商家开店工具
再做能力商品标准
再做买家需求入口
再做报价和订单
再做担保交易和履约
再做评价与评分
再做 AI 可读接口
再做 Agent 自动采购
```

一句话总结：

> **平台不靠概念取胜，而靠交易闭环取胜；不靠限制行业取胜，而靠统一规则取胜；不靠一开始全自动取胜，而靠先让商家、买家、平台三方真实成交取胜。**
