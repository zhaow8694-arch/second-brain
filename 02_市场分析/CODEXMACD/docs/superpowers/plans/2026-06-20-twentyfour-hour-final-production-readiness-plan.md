# 24小时无人值守计划（最终态推进版）

## 一、目标与范围

### 目标
1. 在不改核心交易逻辑的前提下，完成剩余关键测试并形成可复用归档。
2. 消除阻断“可实盘”决策的证据缺口：固定点差/滑点执行风险、月度尺度的稳定性与泛化风险。
3. 输出可用于下一窗口无缝接手的完整状态、结果、参数与报警记录。

### 范围
1. 以当前主线版本 `SniperTrendEA_v8.67_grokbase_production_ready` 与候选版本（若存在）为主，补齐剩余未完成测试。
2. 所有结果保存到固定目录，不覆盖历史文件。
3. 仍遵循用户既有规则：
   1) Smoke test 失败即停
   2) 回测前先确认写入目录与归档路径有效
   3) 每一批完成后追加 `WORK_LOG.md`

## 二、执行总原则（无人值守模式）

### 一级原则
1. 全程按批次、可复现、可回滚。
2. 无法执行、缺证据、或发现历史文件覆盖风险必须作为 blocker 并停止高优先级测试。
3. 所有新文件采用时间戳后缀，禁止覆盖。
4. 每个批次必须保留 `set + 报告 + 归档摘要 + 日志` 四联动证据。

### 二级原则
1. `B`（保守）与 `C`（激进）并行对照，不靠单一模式下结论。
2. 交易监控日报与触发规则优先于参数“成绩表”，先确认风控可执行。
3. 月度/季度稳定性与执行风险是进入下一阶段的硬门槛。

## 三、时间分配（24 小时）

### 阶段1：0–3 小时（接手与基线重建）
1. 对齐交接：读取 `HANDOFF_NEXT_WINDOW.md`、`WORK_LOG.md`、`monthly_breakdown_core_summary.csv`、`quarterly_breakdown_summary.csv`、`production_readiness_report_*.md`、`forward_monitor_*`。
2. 校验目录：
   1) `E:\CODEXMACD\HCSJ\set`
   2) `E:\CODEXMACD\HCSJ\backtest_archive`
   3) `E:\CODEXMACD\HCSJ\matrix\production_readiness`
3. 进行短 Smoke 回测（1 次）确认 EA 加载、回测器链路、报告输出正常。
4. 追加会话锚点到 `WORK_LOG.md`。

### 阶段2：3–10 小时（固定窗口与交叉验证补齐）
1. 完成三窗口基础回测链（每窗口至少 2 轮）：
   1) 2012–2014
   2) 2015–2019
   3) 2017–2023
2. 每窗口执行顺序：
   1) 样本内参数寻优
   2) 样本外验证
   3) 反向窗口验证（互换训练/验证）
3. 每窗口每一轮输出：
   1) `.set` 文件（含版本与策略标签）
   2) 回测报告文件
   3) 指标 CSV（净利、PF、DD、交易数、胜率、最长连亏）
4. 做每组过拟合初判：
   1) 单区间极值参数标记红线
   2) 跨区间稳定参数先留为候选

### 阶段3：10–16 小时（滑点与固定点差执行闭环）
1. 固定点差核验：
   1) 区分“参数输入点差”与“真实执行点差”差异
   2) 进行放大压力点差测试
2. 滑点核验：
   1) 验证当前环境可用方案（若仍无真实执行模型，提交 blocker）
   2) 记录 0/1/2/3/5/8 点差压测序列
   3) 输出收益衰减与风控触发曲线
3. 形成执行风险对照矩阵：
   1) 原始策略 vs 风险惩罚后策略
   2) 与月度 watch 指标联动，决定是否触发监控红线

### 阶段4：16–20 小时（月度、季度、起止日期平移与时间移位）
1. 月度核心拆解复核：
   1) 计算月度盈利分布、最大单月回撤、连亏月份
   2) 定位 watch 来源：是参数失配还是行情结构转移
2. 起止日期平移测试：
   1) 前移窗口
   2) 后移窗口
   3) 统一对比衰减与波动
3. 区间交叉压力：
   1) 固定点差与滑点组合下再做月度/季度重测
   2) 输出稳定性评级变化表

### 阶段5：20–23 小时（稳健参数确定与反向验证）
1. 反向验证：
   1) 用 2012–2019 寻参，验证 2020–2026
   2) 用 2020–2026 寻参，验证 2012–2019
2. 参数稳定性压力：
   1) 对 top 参数做微扰（±5%）
   2) 估计净利衰减率、PF 波动、DD 波动和稳定度
3. 输出“可执行稳定参数集”非单一最优，明确版本选择 A/B/C 候选

### 阶段6：23–24 小时（汇总与交接）
1. 生成阶段总结（已完成任务、失败/blocker、下一步）。
2. 更新 `WORK_LOG.md`（分批结果+触发规则+incident）。
3. 更新 `HANDOFF_NEXT_WINDOW.md`（剩余任务与接手顺序）。
4. 输出最终判级：
   1) 是否达到 demo-forward 条件
   2) 若通过，进入实盘演练准备清单
   3) 若未通过，输出需优先补齐项

## 四、任务分级

### P0（必须止损）
1. 回测器无法启动或无产出
2. 路径写入失败导致历史文件覆盖风险
3. 基础性能指标文件缺失、不可复核

### P1（核心）
1. 三窗口样本内外完整性
2. 固定点差真实闭环验证
3. 滑点可行验证
4. 月度 watch 改善（至少可解释）

### P2（重要）
1. 反向验证与参数微扰稳健性
2. 起止日期平移测试
3. 固定点差放大+滑点叠加压力

### P3（辅助）
1. 归档索引与可追溯清单自动化
2. 结果图表汇总与参数演化说明
3. 备份式对照：v8.64 与 v8.67 系列表

## 五、产出清单（无人值守结束前必须存在）
1. 全部 set 文件：`E:\CODEXMACD\HCSJ\set`
2. 全部回测报告：`E:\CODEXMACD\HCSJ\backtest_archive`
3. 生产态 readiness 报告更新
4. 监控日报与触发规则执行记录
5. `WORK_LOG.md` 完整追加
6. `HANDOFF_NEXT_WINDOW.md` 明确下一步

## 六、通用停止与降级规则（自动生效）
1. 若任何 P0 触发，立即停止高强度测试，写 blocker。
2. 若同一指标三批连续恶化，立即转入保守参数集重测。
3. 若监控规则触发红色，即刻记录 incident 并暂停新增优化。
4. 无法形成可复核证据时，不得输出“可实盘”结论。

## 七、交接执行说明（下一窗口第一分钟）
1. 打开本计划文件，按阶段顺序执行。
2. 先执行阶段1校验，确认无 blocker。
3. 每完成一个大项，在 `WORK_LOG.md` 写一条并附路径。
4. 每次测试完成后再执行对应下一小项，不跳过分支。
5. 24小时未结束也不要中断，顺延执行“阶段6 收尾任务”。

## 八、24小时任务提前完成后的自动续航策略（剩余时长任意）
1. 当24小时任务提前完成，立即进入“后续加固任务池”，按剩余时长顺序执行，避免返回空闲等待。
2. 目标是把可用结果从“可测”升级为“可复盘、可追责、可实盘前置”。
3. 续航任务默认遵循三层优先级：先证据闭环，再稳健性，再运维预演。

### 任务池A：可复现性与证据完整性（优先级最高）
1. 同批次关键结果复跑1次，做参数/窗口一致性对照。
2. 生成“结果索引表”：测试批次、窗口、参数、文件路径、状态、风险结论一一对应。
3. 交叉审计：逐项检查是否存在缺文件（set、报告、CSV、日志）或命名冲突。
4. 输出“可复盘差异单”：同参数不同窗口结果偏离超过阈值的清单与原因。

### 任务池B：稳健性再验证（优先级次之）
1. 追加未覆盖的时间位移样本与边界窗口验证。
2. 扩展参数微扰测试（`±2% / ±5% / ±8%`）并记录收益、PF、DD斜率变化。
3. 做参数鲁棒性排名稳定度：跨窗口 top 参数一致性与排序相关性。
4. 形成抗过拟合补充说明：为何认为“稳定参数”优于“历史最大值参数”。

### 任务池C：执行风险闭环补缺
1. 继续固定点差与滑点极值测试，补齐二维边界表（点差×滑点）。
2. 输出失败边界：何时触发交易频率崩塌、DD 扩大、或连亏失控。
3. 给出自动降级规则草案：轻微收紧、减仓、暂停开仓、停机。

### 任务池D：前向运行与监控体系
1. 完整演练交易监控日报与触发规则闭环一次。
2. 完善日内单笔日志模板字段与 incident 触发字段映射关系。
3. 输出实盘前置清单：监控人、观察项、报警阈值、回撤应急动作、回退路径。

### 续航执行规则（按剩余时长动态）
1. 必须先完成任务池A，再进入池B/C/D。
2. 每完成一项，在 `WORK_LOG.md` 写入“提前完成续航”条目并打上时间戳。
3. 所有新增产物继续落在固定目录并写明时间后缀，不得覆盖历史版本。
4. 若剩余时长不足以完成某项，必须在 `HANDOFF_NEXT_WINDOW.md` 明确中断点与恢复点。
